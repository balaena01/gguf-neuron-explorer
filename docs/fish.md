# FiSH: 計算で作るニューロン(mode: nw)

この手法を **FiSH**(Formula-instantiated Scene-gated Hidden units)と呼ぶ。すでにある MLP のニューロンを、学習なしで、式から計算した重みで
書き換えて、「鍵が反応する位置(決まった場面)でだけ、方向を書く」ニューロンにする書き込みの方式。ニューロンを足すのではなく、
働きの小さいニューロンを書き換える(足す形は作らない)。コマンドやユニットの名前は中身を表す `nw` のまま。
レシピのユニットとして書き(`mode: nw`)、実行時の LoRA で当てる。

- 位置づけ: [keyed write](keyed-write.md) は、残差に書き込む重み行列に線形の変更 `α d κᵀ` を足す。足す量は鍵の反応に比例するので、
  反応が小さい位置にも少しずつ書き、反応が負の位置では逆向きに書く。nw は、MLP のゲートを使って、反応が小さい位置・負の位置で
  ほとんど書かないようにする。2 つの鍵の「かつ」(場面 かつ 返事の位置)や、足す量の上限も作れる。
- 例は語尾と性格だけを扱う。
- **根拠は Qwen3.5-4B の 2 つの例(語尾・ツンデレ)だけ**で、返事の質は 12 問を読んで分けた数で見ている(§8)。口調の完成度は今後の課題。

## 1. しくみ

### MLP の形

対応するのは、ゲートつきの MLP(SwiGLU、バイアスなし)の dense の層だけ。層の入力を正規化したもの `h` から

```
out = W_down · ( silu(W_gate h) ⊙ (W_up h) )        silu(z) = z · σ(z)
```

を残差に足す。ニューロン `j` は、`W_gate` の j 行(ゲート)・`W_up` の j 行(入力)・`W_down` の j 列(出力)で決まり、
その位置で `silu(gate_j) · up_j` を係数にして、出力の列を残差に書く。

nw は、ふだんあまり働いていないニューロン `j` を選び、この 3 か所を差し替える。ほかのニューロンには触らない。
差し替えたニューロンの元の働きは無くなる(§4)。

### 鍵 1 つの形

```
W_gate[j] ← s·κ        W_up[j] ← κ        W_down[:, j] ← α·d ÷ silu(s)
足す量 = silu(s·ρ)·ρ ÷ silu(s) × α·d            ρ = κᵀh(鍵の反応)
```

`κ` は MLP の入力の空間の鍵(§3)、`d` は書く方向、`α` は強さ、`s` はゲートの倍率(既定 4)。`ρ = 1` でちょうど `α·d` を書く。

鍵の反応 `ρ` に対する足す量(`α·d` を 1 として):

| ρ | −1 | −0.5 | 0 | 0.25 | 0.5 | 0.75 | 1 | 1.5 | 2 |
|---|---|---|---|---|---|---|---|---|---|
| keyed write(比例) | −1 | −0.5 | 0 | 0.25 | 0.5 | 0.75 | 1 | 1.5 | 2 |
| nw、s = 4 | 0.02 | 0.03 | 0 | 0.05 | 0.22 | 0.55 | 1 | 2.29 | 4.07 |
| nw、s = 8 | 0.00 | 0.00 | 0 | 0.06 | 0.25 | 0.56 | 1 | 2.25 | 4.00 |

- 反応が小さい位置では、2 乗に近い形で潰れる(ゲートと入力の両方に鍵の反応が掛かるため)。
- 反応が負の位置では、ほとんど書かない。逆向きには書かない(silu の負の側は小さく、入力も負なので積は小さな正になる)。
  `s` を大きくすると、負の側がよく閉じる。0 と 1 の間の形は `s` でほとんど変わらない。
- **反応が 1 を超える位置では、比例より多く書く**(2 乗で増える)。上限が要るなら「上限つきの形」を使う。

### 鍵 2 つの形(かつ)

```
W_gate[j] ← s·κ_A        W_up[j] ← κ_B        W_down[:, j] ← α·d ÷ silu(s)
足す量 = silu(s·ρ_A)·ρ_B ÷ silu(s) × α·d
```

ゲートに入れた鍵 A が開いていて、かつ入力に入れた鍵 B が反応する位置でだけ書く。例: A = 場面の鍵(お礼を言われた場面の返事の間
ずっと反応する)、B = 位置の鍵(返事の位置 1〜3 で反応する)。

- ゲートの側(A)は、負の反応でほぼ閉じる。
- **入力の側(B)は線形**なので、A が開いている位置で B の反応が負なら、逆向きに書く。`gne nw check` で負の量が出ていないかを見る
  (Qwen3.5-4B のツンデレの例では、逆向きの量は平均 0.03、最大 0.3 ほどだった)。

### 上限つきの形(2 個を組にする)

ニューロン 2 個の差を取ると、足す量に上限を付けられる。バイアスが無いので、「どの位置でもほぼ 1 を返す鍵」`κ1` を定数の代わりに使う。

```
1 個目: W_gate ← s(κ − a·κ1)   W_up ← κ1   W_down ← +α·d ÷ (s(b − a))
2 個目: W_gate ← s(κ − b·κ1)   W_up ← κ1   W_down ← −α·d ÷ (s(b − a))
足す量 = [silu(s(ρ − a)) − silu(s(ρ − b))] ÷ (s(b − a)) × (κ1ᵀh) × α·d
```

silu は大きい入力でほぼ直線なので、2 個の差は一定になる。`ρ < a` でほぼ 0、`ρ > b` でほぼ 1 で頭打ちになる。

| ρ | −0.5 | 0 | 0.2 | 0.4 | 0.5 | 0.6 | 0.7 | 0.8 | 1 | 1.5 | 2 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| s = 16、a = 0.4、b = 0.8(既定) | 0.00 | 0.00 | −0.02 | 0.00 | 0.21 | 0.50 | 0.79 | 1.00 | 1.02 | 1.00 | 1.00 |
| s = 8、a = 0.25、b = 0.75 | 0.00 | −0.06 | −0.03 | 0.27 | 0.50 | 0.73 | 0.92 | 1.03 | 1.06 | 1.00 | 1.00 |

- 既定は、反応 0 の位置で逆向きに書く量が小さい設定にしてある。`s` が小さく `a` が 0 に近いと、silu の負の側の小さな谷が
  反応 0 の位置に来て、**どの場面のどの位置でも**方向の数 % を逆向きに書く(下の行。Qwen3.5-4B では、狙っていない質問の返事の
  言い回しが変わった)。
- この形の鍵 `κ` は 1 本なので、「場面 かつ 位置」を 1 本にまとめた鍵を使う(§3 の位置の鍵がそうなっている)。

### なぜ狙った場面だけになるか

どの形でも、足す量は鍵の反応で決まる。鍵は「書き込みたい位置の活性の平均」から「書き込みたくない位置の活性が張る空間」を除いて
作る(keyed write と同じ式、§3)ので、書き込みたくない位置では反応がほぼ 0 になる。nw はそのうえで、小さい反応をゲートで潰す。
重みの変更は 1 つなのに、位置の条件(`when`)なしで「その状態のときだけ効く」動きになる点は、keyed write・CHiPS と同じ。

### 先行研究との関係

見つけた範囲では、学習済みのモデルのニューロンを、学習なしで計算した重みで上書きする形は見当たらなかった。近いものに、
学習でニューロンを足して誤りを直す Transformer-Patcher と、専用に学習したモデルの中で学習なしの上書きを行う Legible Transformers が
ある。鍵と方向の作り方は keyed write([keyed-write.md](keyed-write.md) §2 の出典)と同じ式を使っている。調べ漏れはありうる。

## 2. 使い方の流れ

例: 褒められた・お礼を言われた場面の返事だけ、口調を変える(`configs/contrast/tsundere_thanks.yaml`)。層は 11・18・23 とする。

```bash
C=configs/contrast/tsundere_thanks.yaml

# 1. 書く方向。同じ返事を両方の条件で読ませた差(--same-reply)を、返事の位置で分けて作る(§5)
gne direction --contrast $C --positions response --response-tokens 120 \
    --same-reply --segments 0,1-3,4- --stack-layers 11,18,23
#    → 方向 tsundere_thanks と、区切りごとの tsundere_thanks.seg0 / .seg1 / .seg2

# 2. 上書きするニューロンを選ぶ(働きの小さい順の表を見て、番号を決める。§4)
gne nw neurons --layers 11,18,23

# 3. 鍵(MLP の入力の空間)。位置の鍵 = 「この場面の返事の、この位置」で反応する鍵
gne direction key --contrast $C --target mlpin --layers 11,18,23 --positions pos:0   --name tt_p0 --subset all
gne direction key --contrast $C --target mlpin --layers 11,18,23 --positions pos:1-3 --name tt_p1 --subset all
gne direction key --contrast $C --target mlpin --layers 11,18,23 --positions pos:4-  --name tt_p2 --subset all
gne nw key --contrast $C --layers 11,18,23 --role one   --name tt_one   --subset all      # ほぼ 1 を返す鍵(上限つきの形用)
gne nw key --contrast $C --layers 11,18,23 --role scene --name tt_scene --subset all      # 場面の鍵(鍵 2 つの形用)

# 4. レシピ(上限つきの形の例。層ごとに、区切り 3 つ × 2 個)
cat > tt_nw.yaml <<'EOF'
name: tt_nw
units:
  - {layer: 11, neuron: 2045, pair: 4648, mode: nw, direction: tsundere_thanks.seg0, key: tt_p0, key2: tt_one, alpha: 0.9}
  - {layer: 11, neuron: 2413, pair: 1881, mode: nw, direction: tsundere_thanks.seg1, key: tt_p1, key2: tt_one, alpha: 0.9}
  # … 層 11 の区切り 2、層 18・23 も同じ形で
EOF

# 5. 確かめる
gne nw verify --recipe tt_nw.yaml                    # LoRA が式どおりに動くか(数秒)
gne nw check  --recipe tt_nw.yaml --contrast $C      # 位置ごとの鍵の反応と、実際に足した量

# 6. 返事を読む・数える
gne steer  --recipe tt_nw.yaml -p "昨日は手伝ってくれてありがとう。" --compare
gne behave --recipe tt_nw.yaml --prompts $C --match "別に|ふん"

# 7. 書き出す(LoRA だけ。焼き込みは無い)
gne nw export --recipe tt_nw.yaml -o tt_nw.lora.gguf        # llama.cpp では --lora tt_nw.lora.gguf
```

ユニットの短い書き方(`--unit`):

| 形 | 書き方 |
|---|---|
| 鍵 1 つ | `L:Nn:nw:aα@方向#鍵` |
| 鍵 2 つ | `L:Nn:nw:aα@方向#ゲートの鍵&入力の鍵` |
| 上限つき | `L:Nn+Nm:nw:aα@方向#鍵&ほぼ1を返す鍵` |

後ろに `!s8`(ゲートの倍率。既定は 4、上限つきは 16)、`!cap0.4-0.8`(上限つきのしきい値 a-b)を付けられる。`@-方向` は α の符号に
畳む。`#鍵~j` は比較用の鍵(ラベルをでたらめに入れ替えて同じ手順で作った鍵)の j 番。YAML では
`{layer, neuron, mode: nw, direction, key, key2, pair, s, cap, alpha}`。

`when` は効かない(LoRA は位置で切り替えられない)。control vector には入らない。

**ほかの介入と一緒に使う。** nw のユニットは、CHiPS(proj)・keyed・gain のユニットと同じレシピに書ける。実行時はアダプタを
並べて当て、書き出しは `gne headproj export --recipe R`(`gne gain` も同じ)で 1 つの LoRA になる(`--bake` は nw があるとエラー)。
同じ層にニューロンの gain と nw の両方があると、どちらも ffn_up を変えるので 1 つにできない(nw だけ `gne nw export` で分ける)。

- **先に当てておく介入(`--iv`)**: 鍵づくり(`gne direction key`・`gne nw key`)、ふだんの働き(`gne nw neurons`)、確かめ
  (`gne nw verify`・`gne nw check`)は、レシピかユニットを `--iv` で渡すと、それを当てた状態で行う(keyed write の `--iv` と同じ)。
  CHiPS のレシピを当てた状態でニューロンを作るときに使う。
- **逆の順**: nw のレシピを当てた状態を対照集合の片側にする(`recipe_a` / `recipe_b` に nw のレシピの名前を書く)と、その状態から
  方向を作り、`gne heads pipeline` を回せる(側の介入は LoRA で当たる。対照集合の仕組みそのまま)。nw は書く層より下の状態を
  変えず、質問の最後の位置では位置 0 用のニューロンしか働かないので、方向の位置は `--positions response` にする(既定の last だと、
  下の層の方向の長さが 0 になって強さの配分で止まることがある)。

MCP では `direction`(same_reply・segments・stack_layers)、`direction_key`(target="mlpin"、positions="pos:1-3"、role="scene" / "one")、
`nw_neurons`・`nw_check`(ジョブ)、`nw_verify`、`nw_export`。Python では `Session.direction` / `direction_key` / `nw_neurons` /
`nw_verify` / `nw_check` / `nw_export`、実行時の LoRA は `Session.lora_for(recipe)` に入る。

### Web UI だけで作る(direction ビューの「FiSH」)

`gne serve` の direction ビューの「FiSH」のタブで、上のコマンドと同じことを順に行える。層と強さは使う人が入れる(自動では決めない)。

1. **対照集合**: 「JSON を書く(ひな形)」で `configs/fish/` のひな形(6 つ。下の表)を選ぶと入力欄に入るので、
   `system_a`(出したい口調の指示)、`user_prompts`(狙う場面の質問、30 問ほど)、`dont_touch`(口調を変えたくない場面の質問の群)を
   書き換える。「ファイルを選ぶ」で `configs/contrast/` の YAML も使える。CHiPS のレシピを当てた状態で作るときは「先に当てておく
   レシピ(iv)」に保存したレシピの名前を入れる。
2. **層**(例 11,18,23)、**位置の区切り**(既定 0,1-3,4-)、**形**(既定は上限つきの 2 個組)、**強さ**(既定 0.9)を入れる。
3. **「まとめて作る」**を押すと、方向 → ニューロンの表 → 鍵 → ユニット → そのユニットを当てた状態で鍵を作り直す → 式どおりか →
   足した量、を 1 つのジョブで回す(進み具合・見積もり・「止める」が出る)。ニューロンは表の上から必要な個数(既定の候補)を使い、
   どれを使ったかが出る。段ごとのボタン(「方向を作る」「ニューロンの表を出す」「鍵をまとめて作る」「このレシピを当てた状態で鍵を
   作り直す」「式どおりか確かめる」「足した量を測る」)で 1 段ずつ進めてもよい。
4. 結果を見る:
   - **方向**: 層 × 区切りごとの長さと、今までの作り方との向きの近さ(cos)。
   - **ニューロンの表**: 層ごとに、ふだんの働きの小さい順(最大・平均・順位)。既定の候補にチェックが付いていて、チェックで選び直せる
     (層 1 つに要る数 = 区切りの数 × 形の個数。選び直したら、鍵の作り直しと確かめをやり直す)。
   - **鍵**: 鍵ごと・層ごとに、鍵の反応の差(書き込みたい位置 − 書き込みたくない位置)と、比較用の鍵(ラベルをでたらめに入れ替えた鍵)の
     95% 点。作成に使った例での値なので甘い。
   - **確かめる**: 式どおりか(層ごとの誤差と ○ / ×)と、場面・返事の位置ごとに実際に足した量。狙う場面のその区切りの位置で 0.5 未満は
     黄(足りない)、書き込みたくない位置で 0.2 以上は赤。
5. **「レシピに足す」**でレシピのタブに入る。そこでチャットで試し、保存し、「nw の LoRA を書き出す」で llama.cpp 用のアダプタにする。
6. **「7. 返事を読む」の「レシピを当てて返事を作る」**で、ユニットだけを当てて(system の指示は付けない)、狙う場面の質問と書き込みたくない
   場面の質問に答えさせ、返事を並べて読む(`gne behave` と同じ数え方の、一致・繰り返し・空・切れた数も出る)。既定は対照集合の先頭の
   質問(鍵づくりに使った質問なので甘い)。作成に使っていない質問で見るには「狙う場面の質問を自分で入れる」に 1 行 1 問で入れる。

#### ひな形(`configs/fish/`)と使い分け

どれも例は語尾・性格・口調。**試したのは Qwen3.5-4B(Q8_0)で各 1 回**で、返事は数問〜12 問を読んだだけ(1〜2 問の差は誤差)。
結果はひな形の説明(画面に出る)にも書いてある。層は入っていないので、使う人が入れる(下の「試した層」は、今までの実験で使ってきた層を
そのまま使ったもので、選び方の根拠は無い)。

| ひな形 | 何をするか | 書く位置・形 | 試した層・強さ | Qwen3.5-4B での結果 |
|---|---|---|---|---|
| `tone_in_scene.json` | 特定の場面の返事の口調を変える(お礼を言われたときだけツンデレ) | 返事の位置 0 / 1-3 / 4-、上限つきの 2 個組 | 11,18,23・0.9 | 12 問で性格らしい返事 5〜7 問、壊れ 0。ふつうの質問は変わらない |
| `always_persona.json` | いつでも口調を変える(元気でくだけた口調)。dont_touch なし | 同上 | 11,18,23・0.9 | 相談・おすすめの 6 問中 5 問でくだけた口調、計算・事実の 6 問は敬体のまま。関西弁の指示では言い回しが出なかった |
| `sentence_end.json` | 文末の言い方を変える(です・ます → のだ) | `before:(です\|ます)。`、鍵 1 つ、方向は今までの作り方 | 30・4 | 8 問中 6 問で「なのだ」。崩れた言い方(「なのだとか」)が混じる。英語は変わらない |
| `scene_and_sentence_end.json` | 場面 かつ 文末(雑談のときだけ「のだ」) | `before:…`、鍵 2 つ(ゲート = 場面の鍵、入力 = 文末の直前の鍵) | 30・4 | 雑談 8 問中 5 問に「のだ」(一部の文だけ、弱い)。計算・事実 6 問は敬体のまま、うち 1 問は答えの中身が変わった |
| `two_personas.json` | 2 つの性格の違いだけを書く(system_a = 冷たい、system_b = 温かい) | 返事の位置、上限つき | 11,18,23・0.9 | system_b を付けた 6 問とも、短くそっけない返事に。逆向きは中途半端だった |
| `after_chips.json` | CHiPS のレシピを当てた上に足す(iv に名前を入れる) | 返事の位置、上限つき | 11,18,23・0.9 | 手元の小さな proj のレシピで流れだけ確かめた。実際の CHiPS のレシピとの組み合わせは未確認 |

- **文字の直前に書く(`before:<正規表現>`)**: 「位置の区切り」の欄(表の `fish.segments`)に、返事の位置の区切りの代わりに書く。方向は
  区切らず(名前は `<名前>` のまま)、下の層の残りも使わない。書くとその文字が出なくなるので、当てた状態での鍵の作り直しはしない
  (`fish.rekey: false`。指定しても行わず、結果の注に出る)。足した量は、何も当てずに作った返事をレシピを当てて読み、「一致の直前」と
  「それ以外」に分けて出す。強さは 1 では足りず、例では 4 を使った(keyed write の語尾の例と同じ)。
- **両側に指示がある対照集合(system_b)**: 鍵・足した量・返事の確かめは、system_b を付けた状態で行う(使うときも system_b を付ける)。
  「同じ返事を両方の条件で読む」は、system_a で作った返事を system_a と system_b の両方で読んだ差になる。
- **表の `fish` に書ける設定**: `segments`・`form`・`alpha`・`same_reply`・`stack`・`rekey`・`pseudo`・`max_tokens`・`response_tokens`・
  `iv`(・`layers`)。ひな形を選ぶと欄に入り、書いていない設定は既定に戻る。

ジョブは `fish_pipeline`(まとめて)、`fish_direction`・`nw_neurons`・`fish_keys`・`fish_verify`・`fish_check`・`fish_behave`(段ごと)。鍵の名前は
`<名前>_p<i>`(区切り i の位置の鍵)、`<名前>_scene`(鍵 2 つの形)、`<名前>_one`(上限つきの形)、当てた状態で作り直した鍵は `<名前>_r_…`。
方向は `<名前>`(区切り i は `<名前>.seg<i>`)、今までの作り方で作った比べ用の方向は `<名前>_old`。

## 3. 鍵(MLP の入力の空間)

nw の鍵は、ゲート・入力の行に入れるので、**MLP の入力(正規化の後)の空間**のベクトル(`--target mlpin`、長さ n_embd)。
keyed write の ffn の鍵は ffn_down の入力(ニューロンの活性)の空間で、次元が違うので使い回せない(エラーになる)。
式は keyed write と同じ(`κ = k / (μᵀk)`、`k = μ − Q Qᵀ μ`)。比較用の鍵も同じ手順で作る。

| 鍵 | 作り方 | 反応する位置 |
|---|---|---|
| 位置の鍵 | `gne direction key --target mlpin --positions pos:1-3` | 対照集合の質問(狙う場面)への返事の、位置 1〜3。同じ返事のほかの位置と、dont_touch の質問の返事では反応しない。「場面 かつ 位置」を 1 本にまとめた鍵になる |
| 場面の鍵 | `gne nw key --role scene` | 狙う場面の質問への返事の間ずっと。dont_touch の質問の返事では反応しない |
| ほぼ 1 を返す鍵 | `gne nw key --role one` | どの位置でもほぼ 1(上限つきの形で、バイアスの代わりに使う) |
| 文字の手前の鍵 | `gne direction key --target mlpin --positions "before:(です\|ます)。"` | keyed write の (b) と同じ位置の取り方(語尾の例) |

- **位置の番号**: 位置 k = 返事の k 番目のトークンを決める位置。位置 0 = 生成プロンプトの最後のトークン = 返事を書き始める直前。
  `pos:0`、`pos:1-3`、`pos:4-`(4 以降)と書く。
- **位置の鍵では、dont_touch の群は返事の全部の位置が書き込みたくない位置になる**(群に書いた positions は使わず、返事を生成して
  全部の位置を Q に入れる。出力の注に出る)。区切りの外や返事の冒頭だけだと、ほかの場面の同じ区切りの位置で鍵が反応した
  (Qwen3.5-4B の例で、ふつうの質問の位置 4 以降に、狙う場面の 0.5〜0.8 倍の量を書いた。全部の位置を入れると平均 0.03 以下)。
- **場面の鍵には dont_touch が要る**(反応させたくない質問の群。ふつうの質問、計算や事実の質問など)。比較用の鍵は、質問のラベル
  (狙う質問か、dont_touch か)をでたらめに入れ替えて作る。dont_touch の質問が少ないと、狙っていない質問の位置 0 に反応が残る
  (Qwen3.5-4B の例で、12 問のとき 0.1〜0.2)。
- **書き込みを当てた状態で作る**: 書き込みが効くと、返事も内部の状態も変わる。鍵を無介入の返事だけで作ると、書いた後の状態で
  反応がずれる(2 層目以降で弱くなる、位置の鍵が位置 4 以降でも反応する、など)。`--iv <レシピ>` で、そのレシピを当てた状態の
  返事と活性から作り直せる。1 回目は無介入で作り、できたレシピを `--iv` にして作り直す。
- 作成に使っていない質問で確かめるのは `gne nw check`(§6)。`gne direction key-check` は、位置の鍵・文字の手前の鍵には使える。

## 4. 上書きするニューロンを選ぶ

```bash
gne nw neurons --layers 11,18,23 [--top 20] [--sort sum|max|mean]
```

層ごとに、各ニューロンのふだんの働き(`|silu(gate)·up| × ‖down の列‖` = 1 位置で残差に書く長さ)を、ふつうの質問への無介入の
返事と既定のコーパスで測り、働きの小さい順の表を出す。既定の並べ方は「最大の順位 + 平均の順位」(`sum`)。**表を見て使う人が
選び**、番号をユニットに書く(自動では決めない)。

分かっていること(Qwen3.5-4B、1 例):

- **まったく働いていないニューロンは無かった。** 4 つの層のどれでも、いちばん働きの小さいものが、どこかの位置で MLP の出力の
  1.4〜2.7% の長さを書いていた。選べるのは「働きがいちばん小さいニューロン」で、その元の働きは上書きで無くなる。
- **どれを選んでも結果は変わらなかった。** 語尾の例で、表の上位から 3 個を 1 個ずつ試して、足した量は同じ、返事の数の差は
  1〜2 問(誤差の範囲)だった。ニューロンを消しただけでも、greedy の返事の言い回しは 12 問中 7〜8 問で変わる(口調・内容・正答は
  同じ)。わずかな違いで生成が枝分かれするためで、「無介入との文字の一致率」は効き目の比べに使えない。
- 最大だけで選ぶと平均がふつうのものが混じり、平均だけで選ぶと、まれに大きく働くもの(コードなど特定の文で発火)を拾う。
  重みの大きさ(行・列の長さの積)が小さいものは、かえってよく働くニューロンだった。

## 5. 書く方向

方向は `gne direction` の方向を、その層の平均差そのままの大きさで使う(keyed write と同じ。α = 1 で観測した差を 1 回分書く)。
作り方を選べる([keyed-write.md](keyed-write.md) §19):

- `--same-reply`: 同じ返事(A 側の返事)を、A 側の条件と B 側の条件の両方で読ませた差。条件の違いだけの成分になる。
  既定(今までの作り方)の方向には「読んでいる語の違い」から来る成分が約半分入り、それを書き続けると繰り返しに落ちた。
- `--segments 0,1-3,4-`: 返事の位置で分けた方向。区切り i は `NAME.seg<i>` という名前で使う。返事を書き始める位置の差は、
  後ろのほうの差と向きも大きさも違った(位置 0 は約 2 倍の長さ)。
- `--stack-layers 11,18,23`: 区切りつきの方向を、複数の層に重ねて書く前提の値にする。下の層に足した分は上の層に伝わるので、
  平均差をそのまま各層に足すと足し過ぎになる。上の層の値を「下の層に足した後の残り」にする。

## 6. 確かめる

```bash
gne nw verify --recipe R            # 式どおりに動くか
gne nw check  --recipe R --contrast C [--subset odd] [--replies own|base]
```

- **verify**: 層ごとに、その層のユニットだけの LoRA を当てて短い文を読ませる。上書きしたニューロンのゲート・入力が
  (新しい行)ᵀh になっているか、活性が silu(ゲート)·入力 か、**ほかのニューロンの活性が変わっていないか**、MLP の出力の変化が
  式どおりかを見る。LoRA は float に戻した元の行・列を引く形なので、量子化のままの掛け算との小さなずれ(1〜2%)は残る。
- **check**: 狙う場面(対照集合の質問)と、書き込みたくない場面(dont_touch の群)で、返事の位置 0 から順に、ユニットごとの鍵の反応と
  実際に足した量(`α·d` を 1 として)の平均・最小・最大を出す。`--replies own` は、レシピを当てて作った返事を当てたまま読む
  (実際に起きること。繰り返しに落ちた返事の数も出る)。見るところ:
  - 狙う場面で、足す量が 1 から大きく外れる位置(多すぎ・少なすぎ。区切りの変わり目は谷になりやすい)。
  - 書き込みたくない場面で、0 から離れる位置。
  - 負(逆向き)になる位置(鍵 2 つの形の入力の側、上限つきの形の緩い設定)。
- 最後は、返事を読む。正規表現の一致は当てにならない(繰り返しの中の語も数える)。

## 7. 書き出しと制限

- **実行時の LoRA だけ**(`gne nw export`、llama.cpp の `--lora`)。ニューロン 1 個につき、ffn_gate・ffn_up・ffn_down の 3 つの
  テンソルに階数 1 の差し替え(行・列を「新しい値 − 元の値」で置き換える)。Qwen3.5-4B でニューロン 1 個 約 0.14 MB。
- **焼き込みは無い**(`--bake` ははっきりしたエラーになる)。Q8_0 は 32 個の重みが 1 つの倍率を共有する。ffn_gate・ffn_up の行は
  行ごとに量子化し直せる(誤差 約 0.6%)が、ffn_down の 1 列は、1 行につき 1 個ずつ別のブロックに入っている。方向の要素は
  同じブロックのほかの重みより 100 倍ほど大きく、倍率を保つと頭打ちになって誤差が 94〜99% になり、倍率を上げると同じブロックの
  ほかの 31 個のニューロンの出力が壊れる。ffn_down だけ F16 にする焼き込みは作れるが、今は入れていない。
- **対応する形**: ゲートつきの MLP(SiLU のゲート × 入力、バイアスなし)の dense の層。確かめてある arch は llama・qwen2・qwen3・
  qwen35。ほかの arch、ゲートの無い MLP、バイアスや倍率(.scale)のある MLP、MoE の層、MTP の層、最終層は、エラーになる。
- **同じレシピの proj・keyed・gain と一緒に 1 つの LoRA にするなら** `gne headproj export`(§2)。
- **UI**: レシピの欄で、nw のユニットの表示・強さの変更・保存・LoRA の書き出し(「nw の LoRA を書き出す」)ができる。鍵づくり・
  ニューロンの表・確かめの画面は無い(CLI か MCP で行う)。

## 8. 分かっていること(Qwen3.5-4B、2 例。数値は [verification.md](verification.md) §22)

- **語尾(狙った位置が返事の途中に散らばる例)**: 鍵 1 つの形で、狙った位置に足す量を keyed write にそろえると、狙っていない位置に
  足す量(大きさの平均)は約 1/5、英語の返事では約 1/10、逆向きに書く位置は 41% から 0% になった。返事の数(「のだ」の入った返事、
  壊れた返事)は keyed write と同じくらいで、入り方の不自然さも同じだった。
- **性格(狙った位置が返事の書き始めにある例)**: 鍵 1 つの形は、keyed write と同じく繰り返しに落ちた。書いた後も鍵が反応し
  続けるためで、ゲートの形を変えても変わらない。
- **最初の数トークンだけ書いても、口調は変わらなかった。** 指示を読ませたときの内部の状態そのものを、全部の層・最初の 8 位置に
  移し替えても、性格らしい返事は 12 問中 4 問(指示を付けると 11 問)。書き出しは同じになるが、その後で元の口調に戻る。
  **口調を変えるには、返事の間ずっと書き続ける必要があった。**
- **位置で 3 つに分けた方向(`--same-reply`)を書き続ける**と、制御ベクトル(層の出力に直接足す)で 12 問中 7 問が性格らしい
  返事になり、壊れは 0 だった。同じ形を nw で作ると、いちばん良かった設定(上限つきの形、0.9 倍)で 5 問・壊れ 0。
  乱数を変えると大きく揺れた(サンプリングの種ごとに 12 問中 1〜5 問)。
- **強さの幅は狭い。** 制御ベクトルでも、0.5 倍では素のまま、1.5 倍では繰り返しが出た。nw は足す量が鍵の反応で変わるので、
  同じ返事の中でこの幅をはみ出しやすい。上限つきの形はばらつきを減らすが、区切りの変わり目に量の谷ができる。
- **狙っていない場面は守れた。** 場面の鍵・位置の鍵が本物なら、計算や事実の質問・ふつうの質問では足す量が 1〜5% で、正答も
  口調も変わらなかった。比較用の鍵に替えると、それらの質問の口調が崩れた。

限界: モデル 1 つ・例 2 つで、返事の質は 12 問(サンプリングで 36 問)を読んで分けた数。1〜2 問の差は誤差。口調の男女など、
指示を付けたときの返事との違いは残っている。
