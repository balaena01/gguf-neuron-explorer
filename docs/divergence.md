# 設計とのずれ

現行コードが設計書(本体設計 `gguf-neuron-explorer-DESIGN.md`、別冊 UI 設計、変更指示 CHANGE-01〜07)と違うところの一覧。変更指示を当てる前に洗い出し(CHANGE-01 §0.1)、変更のたびに更新する。

設計書はリポジトリに含めていない。Phase 0〜5 で見つけたずれと設計への追記は、`docs/verification.md` の各「設計と違った点・設計への追記」節(F1〜F73)に理由つきで記録してある。ここでは変更指示に関係するものだけをまとめる。

| `when=ramp` の prefill | 記述なし | prefill は倍率 a で足す | 「冒頭だけ強く」が prefill から効くように |

## 3. CHANGE-07(keyed write)で生まれたずれ

手法の説明は [keyed-write.md](keyed-write.md)、検証は `docs/verification.md` §21。CHANGE-06 との関係: CHANGE-06(proj)は選んだヘッドの書き込みのうち方向に沿った成分を変える(どの方向を変えるか)。CHANGE-07(keyed)は、残差に書き込む重み行列の入力の活性に鍵が反応する状態でだけ方向を書く(どの状態で書くか)。両者は直交し、同じ LoRA に重ねられる。

**この節の言葉。** 鍵が反応してほしい位置を「書き込みたい位置」、反応してほしくない位置を「書き込みたくない位置」と書く(コードと結果の名前では `_a`・`_b`)。鍵の反応の強さ ρ = κᵀx は、書き込みたい位置の活性の平均 μ で 1 になる(κᵀμ = 1)。key-check の選択性は、書き込みたい位置での反応の平均と、書き込みたくない位置での反応の平均の差(eval の選択性は下の表の「評価の選択性」)。Q は、鍵が反応しないようにする部分空間(書き込みたくない位置と dont_touch の群の活性の行が張る。「Q に入れる」はその行に加えること)。比較用の鍵は、ラベルをシャッフルして同じ手順で作った鍵(`NAME~j`、引数・結果の `pseudo`)。

ユーザーの決定(2026-11-07): (1) 鍵の書き込みたい位置は、(a)(system・レシピの状態)と (b)(推論時と同じ文脈の返事の、変えたい位置)の両方の作り方を入れ、例は (b) で書く。(2) α は方向をそのままの大きさで掛ける倍率(d_L = r_L)。(3) 初版の範囲は変更指示のとおり全部(UI の鍵パネルとヒストグラム、E.1 の、比べる方式の強さを keyed にそろえる処理、attention、MoE の shared expert と専門家ごと、他の介入を当てた状態での鍵づくり)。
