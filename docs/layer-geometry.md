# 層の幾何(`gne heads geometry`)— 層ごとの更新ベクトルを比べる

CHiPS([head-component-steering.md](head-component-steering.md))は、層ごとに 1 本の方向ベクトル `r̂_l` を使い、選んだ部品の書き込みからその成分を弱める。この道具は、その前提を確かめるための診断に使う。

- 振る舞いの違いは、層ごとに 1 本の方向で捉えられているか。
- 層ごとに別々の向きなのか、少数の共通の向きの組み合わせなのか。
- 1 本の方向で消しても残る、質問ごとのばらつきの向きはあるか。

モデルは流さない。`gne heads writes` が保存した配列だけで計算するので、GPU は使わず、数秒で終わる。この道具はモデルも重みも変えない。2 本目の向きが応答に効くかは、方向ベクトルとして保存して(§3.10)、今の道具で確かめる。

---

## 1. 材料

`gne heads writes --name <方向>`(`heads pipeline --rank writes` の中でも作られる)が保存する `<root>/heads/<model_id>/<名前>.writes.npz` の、層ごとの更新の差(形式は [head-component-steering.md](head-component-steering.md) §3.9 の「保存の形式」)。

```
d_l = (A 側の質問で、層 l が残差に足した量の平均) − (B 側の質問での同じ平均)
```

- 測る位置(既定はプロンプトの最後のトークン)での平均。正規化の前の値。
- 層全体の更新は、注意の出力全体(線形注意の層では線形注意の出力)と MLP の出力全体の和。
- 質問を偶数番目・奇数番目に分けて作った半分ずつの差 `d_l^h0`・`d_l^h1` も入っている。

**質問ごとの更新(`--save-q`)。** 同じ層の中で質問ごとの差を分解する(§3.7)ことと、ラベル入れ替えの基準(§3.6)には、質問ごと・層ごとの更新が要る。`gne heads writes --name <方向> --save-q` で、別のファイル `<名前>.writes_q.npz` に保存する(既定では保存しない。`.writes.npz` の形は変わらない)。モデルを流し直す必要はなく、書き込みの順位づけで捕まえた値から作る。

| 配列 | 形 | 中身 |
|---|---|---|
| `q_upd_attn_a`・`q_upd_attn_b`・`q_upd_mlp_a`・`q_upd_mlp_b` | (その側の質問の数, 層の数, n_embd) | 質問ごとの更新(注意の出力全体・MLP の出力全体)。float16 で、層ごとに最大の絶対値が 1024 になるよう割ってある |
| `q_scale_<同じ名前>` | (層の数,) | 割った数(読むときに掛け戻す) |
| `q_index_a`・`q_index_b` | (質問の数,) | 対照集合のその側の質問の番号 |
| `q_paired` | () | 対になった対照集合か(両側で同じ質問、system やレシピだけが違う) |
| `q_contrast`・`q_contrast_sha` | () | 対照集合のファイルと、その中身の sha(質問の文を引くのに、同じものか確かめる) |

大きさは、Qwen3.5-4B(31 層 × 2,560)の各側 16 問で約 10 MB、各側 64 問で約 41 MB、SenseNova-Loop-9B(55 層 × 4,096)の各側 16 問で約 29 MB。読むとき、質問ごとの平均が `.writes.npz` の側ごとの平均と合わなければ(材料を作り直したあとの古いファイルなど)、使わずに知らせる。

## 2. 使い方

```bash
gne heads writes --name <方向> --save-q --verify-top 0      # 材料(質問ごとの更新も)。確かめを省けば 1 分前後
gne heads geometry --name <writes の名前>
gne heads geometry --name <writes の名前> --parts attn,mlp --export-direction <名前>_v2 --export-from svd-rows:2
```

| 指定 | 既定 | 中身 |
|---|---|---|
| `--name` | (必須) | heads writes の保存名 |
| `--parts` | `layer` | 行の単位。`layer`(層ごとに 1 行)/ `attn,mlp`(注意の出力全体と MLP の出力全体の 2 行。行と列が 2 倍)/ `layer,attn,mlp`(3 倍)。中身の無い行は除く |
| `--normalize` | `both` | 特異値分解の前に行の大きさをそろえるか(`rows` / `none` / `both`) |
| `--top-k` | 6 | 寄与率・説明率・保存する向きを何番目まで出すか |
| `--layers` | 全部 | 使う層(`10-30` など) |
| `--min-half-cos` | 0.5 | 信用しない印の基準(半分どうしの cos がこれ未満の行) |
| `--permutations`・`--perm-seed` | 200・0 | ラベル入れ替えの基準の回数(質問ごとの更新があるときだけ。0 で切る) |
| `--compare` | `<名前>_r1` などがあればそれ | 比べる方向ベクトル(カンマ区切り。既定は heads refine の方向) |
| `--exclude-dims` | なし | 計算から除く残差の次元(行ごとの「上位の次元」を見て手で決める) |
| `--export-direction`・`--export-from` | なし | 向きを方向ベクトルとして保存する(§3.10) |
| `--out-name` | `--name` | 結果の保存名 |

結果は `<root>/heads/<model_id>/<保存名>.geometry.json`(まとめ)と `.geometry.npz`(類似度の行列・向き)。MCP のツール `heads_geometry`、Python API `Session.heads_geometry` / `heads_geometry_export` でも同じことができる。

**UI。** 上の「探す」の群の「層の幾何」。材料を選んで「計算する」(その場で計算する。ジョブにはしない)。層 × 層のヒートマップ(負は青・0 は灰・正は赤。範囲は ±1 と「対角以外の最大」を切り替える)、縁に層の種類と何回目か、信用しない行の斜線、大きさの棒とラベル入れ替えの 95% の印。特異値分解の寄与率と基準、モードごとの層のパターン、方向ベクトルとの cos、質問に沿った分解の表(行を選ぶと、質問ごとの cos を質問の文つきで並べる)、refine の方向との比べ、方向ベクトルとして保存。値はマウスでも、図を選んで矢印キーでも図の下の行に出て、表でも読める。

## 3. 計算

### 3.1 行

各行は 1 本のベクトル `x_i`(長さ n_embd)。`--parts layer` なら `x_i = d_{l(i)}`。行を上から並べた行列を `X`(行の数 × n_embd)、各行を大きさで割ったものを `X̃` とする。部品の行を足すときは、部品ごとにまとめて層の順に並べる(層全体の行の全部 → 注意の行の全部 → MLP の行の全部)。

### 3.2 層 × 層のコサイン類似度

1. 各行の大きさ `‖x_i‖` を出す。
2. `C_ij = (x_i · x_j) / (‖x_i‖ ‖x_j‖)`。行列で書くと `C = X̃ X̃ᵀ`。

小さな例(3 行、3 次元):

```
x_1 = (2, 0, 0)   ‖x_1‖ = 2      x̃_1 = (1, 0, 0)
x_2 = (1, 1, 0)   ‖x_2‖ = 1.414  x̃_2 = (0.707, 0.707, 0)
x_3 = (0, 0, 3)   ‖x_3‖ = 3      x̃_3 = (0, 0, 1)

C = | 1      0.707  0 |
    | 0.707  1      0 |
    | 0      0      1 |
```

`x_1` と `x_3` は大きさが違っても向きが直交しているので、cos は 0。cos は大きさを見ないので、大きさの棒を横に並べる。

- 対角以外の |cos| の平均・最大を出す。層全体の行と、同じ層の注意・MLP の行の組は、和の関係なのでそれだけで cos が高くなるため、このまとめの数からは除く(行列には残す)。
- ループのモデル(同じ重みを 2 回使う、[sensenova_loop.md](sensenova_loop.md))では、同じ重みの 1 回目と 2 回目の組 (l, l + 24) を表にする。行列の中では、対角線から 24 段ずれた線に並ぶ。

### 3.3 方向ベクトルとの関係

材料と同じ名前の方向ベクトルを読み、行ごとに出す。

1. `cos(x_i, r̂_l)`: その行の更新の差と、CHiPS がその層で使う方向との cos。2 乗が、その方向に沿う割合。
2. `cos(x_i, r̂_S)`: 選ぶ層の方向との cos(heads writes の点数は、選ぶ層への直接の寄与で測るので)。
3. 材料の確かめ: 更新の差を層 0 から足し上げた `Σ_{l'≤l} d_l'` と、方向ベクトルの元の値 `r_l`(残差の平均の差)の cos。測る位置が両側で同じテンプレートのトークンなら、埋め込みの差は 0 で、両者は一致する。選ぶ層で 0.9 未満なら「方向ベクトルが材料と別の質問・位置で作られた疑い」と知らせる。
4. 行ごとに、`‖x_i‖²` のうち大きい順に 5 つの次元が占める割合と、その次元の番号(少数の次元が cos を決めていないかの目安)。

### 3.4 特異値分解(層に沿った分解)

1. `X = U Σ Vᵀ`(行の大きさをそろえる版は `X̃` で)。
2. 寄与率 `σ_k² / Σ_j σ_j²` と累積。
3. `U` の k 列目 = k 番目のモードの層に沿ったパターン、`V` の k 行目 = 残差の空間での向き。符号は、`U` の列の和が正になる向きにそろえる。
4. 層ごとの説明率: 上位 k 本の向きで、その行のどれだけを説明できるか `‖V_kᵀ V_k x_i‖² / ‖x_i‖²`。
5. 基準(どれも、データの全体に対する割合で並べる):
   - **行が直交していたときの値**: 行の大きさをそろえる版は全部 1 / 行の数。そろえない版は `‖x_i‖²` を大きい順に並べた割合。そろえない版の上位がこの値とほぼ同じなら、上位のモードは「どの層の更新が大きいか」を映しているだけ。
   - **雑音の目安**: 半分どうしの差 `N = (X_h0 − X_h1)/2` の特異値の 2 乗 ÷ `‖X‖²`(§3.5)。
   - **ラベル入れ替えの 95%**(質問ごとの更新があるとき、§3.6)。
6. 半分ずつでの確かめ: 偶数番目の質問から作った `X_h0` で求めた上位 k 本で、奇数番目の `X_h1` をどれだけ説明できるか(逆も、その平均)と、半分どうしの上位 k 本の部分空間の重なり(主角の cos の 2 乗の平均。1 = 同じ部分空間)。

### 3.5 信頼性(半分ずつ)

1. 行ごとの `cos(x_i^h0, x_i^h1)`。`--min-half-cos` 未満の行に「信用しない」の印を付ける(図では斜線、表では ×)。計算からは除かない。
2. 雑音の大きさの目安 `‖(x_i^h0 − x_i^h1)/2‖ / ‖x_i‖`。両側の質問の数が偶数なら `d = (d_h0 + d_h1)/2` になり、`(d_h0 − d_h1)/2` は狙った違いを含まず、`d` と同じ大きさの雑音を持つ。奇数ならずれるので知らせる。
3. 偶数・奇数の分け方は無作為ではない。質問の並びに偏りがあると、それも映る。

### 3.6 ラベル入れ替えの基準(質問ごとの更新が要る)

1. 狙った違いを抜く: 対にならない対照集合(側ごとに別の質問)は各側の平均を引く。対になった対照集合は、質問ごとの差 `u_q^A − u_q^B` から平均の差を引く。
2. 対にならない対照集合は、両側の質問を混ぜて元と同じ数ずつに分け直し、差を作る。対になった対照集合は、質問ごとの差の符号を無作為に入れ替えて平均する。
3. 入れ替えた差ごとに、行の大きさ・半分どうしの cos・行どうしの |cos|・特異値分解の寄与率を出し、`--permutations` 回の 95 パーセンタイルを「質問ごとのばらつきだけでも出る値」として並べる(大きさ ÷ 基準、ヒートマップの値に添える基準、基準を超える組の数、寄与率の基準)。
4. 1 で平均を引くのは、引かずに入れ替えると狙った違いが入れ替えた差にも残り、層どうしの cos の基準が狙った違いの形を含んでしまうため(各側 64 問の対になった対照集合で、どの組も基準を超えなかった)。
5. 分かるのは「その値が、質問ごとのばらつきだけで出る値より大きいか」だけ。狙った振る舞いの違いか、話題・長さ・言語の違いかは分からない。

### 3.7 同じ層の中で、質問ごとの差を分解する(質問ごとの更新が要る)

層(と部品)ごとに:

1. 質問ごとの差 `e_q`。対になった対照集合では `u_q^A − u_q^B`、対にならない対照集合では `u_q^A − ū^B`(A 側の質問の更新 − B 側の平均)。行の平均は `d_l`。
2. 1 本の方向での説明率 `Σ_q (e_q · v)² / Σ_q ‖e_q‖²`(`v` = 平均の向き `d̂_l`・`r̂_l`・`r̂_S`)。
3. 取り残し: `e_q` から `d̂_l` の成分を引いたもの。全体に対する割合と、その特異値分解の上位の向き(1 本の方向で消しても残る、質問ごとのばらつきの向き)と寄与率。
4. 取り残しの向きの安定度: 偶数番目・奇数番目の質問で別々に求めた 1 番目の向きどうしの |cos|。
5. 対にならない対照集合では、片方の半分で求めた向きに沿った A 側のもう半分の広がり ÷ B 側の質問どうしの広がり(A/B)と、役割を入れ替えた同じ量(B/A)。両方とも 1 より大きいなら、それぞれの側の質問どうしの違い(話題など)の向きで、A 側だけに特有とは言えない。対になった対照集合では出さない。
6. 質問ごとの `cos(e_q, d̂_l)`。信用できる層全体の行で平均して、低い質問を文つきで並べる(heads refine の「残りの質問」と並べて読める)。
7. 向きの数は A 側の質問の数より多くならない。各側 16 問では上位の向きは雑音で決まりやすいので、安定度と並べてしか読めない。

### 3.8 2 本目の方向の候補との比べ

比べる方向 D(既定は heads refine の方向 `<名前>_r1` など)の層ごとの `r̂^D_l` について、`cos(r̂^D_l, r̂_l)`、`cos(r̂^D_l, x_i)`、`cos(r̂^D_l, V_k)`、D の材料(`<名前>_r1.writes.npz`)があれば材料どうしの cos。heads refine の方向は、組を両側に当てた状態で残りの質問だけを A にした残差の平均の差。特異値分解の向きは更新の差。同じ残差の空間の向きとして cos を比べているだけで、意味の違う量どうしの比べになる。

### 3.9 ループのモデル

同じ重みの 1 回目と 2 回目は、入力の残差が違うので、同じ重みでも更新は違ってよい。cos は結果の比べで、重みの比べではない。2 本の流れの中の層の更新は、2 本の平均への増分(`c·y`。[sensenova_loop.md](sensenova_loop.md))。

### 3.10 方向ベクトルとして保存する

`--export-direction NAME --export-from SRC` で、結果の向きを今の方向ベクトルの形(`<root>/directions/<model_id>/NAME.npz`)で保存する。UI では「6. 方向ベクトルとして保存する」。

- `svd-rows:K` / `svd-none:K`: 特異値分解の K 番目の向き。全部の層に同じ向き。
- `within:K`: 各層の層全体の行の、取り残しの K 番目の向き(層ごとに違う向き。質問ごとの更新が要る)。最後の層は材料に入らないので、その層のユニットでは、gne の道具は手前で一番近い層の向きを使う。
- `update` / `update-attn` / `update-mlp`: その層が新しく足した分の向き `d̂_l`(層ごとの更新の差 `d_l` を単位にしたもの。層全体・注意の出力全体(線形注意の層では線形注意の出力)・MLP の出力全体)。層ごとに違う向き。質問ごとの更新は要らない。更新がほぼ 0 の層(層の中の最大の 10⁻⁶ 倍以下。MoE の層の MLP など)と、信用しない印の層(半分どうしの cos が結果の基準未満)は保存せず、知らせに層を並べる。その層のユニットでは、gne の道具は手前で一番近い層の向きを使う。
- 符号は、`svd-*`・`within` はその層の残差の平均の差(元の方向ベクトルの元の値)への射影が正になる向き(`svd-*` は選ぶ層で)、`update` は A 側 − B 側の更新そのものの向き。
- 対照集合・測る位置・基準層は元の方向ベクトルから写す。単位ベクトルなので大きさには意味がなく、方向を足す add の強さには使わない。
- `gne direction score --name NAME`・`gne heads writes --name NAME`・`gne headproj ablate --direction NAME`、レシピのユニット(`L:attn:s1@NAME` など)で使える。`gne heads pipeline --from-direction NAME`(MCP の `from_direction`)で、その向きで順位づけ・配分を最初から流せる(方向づくりを飛ばし、一括の名前の方向として写す。方向を作った対照集合と一括の対照集合の質問が同じと確かめられないときは知らせる)。

**方向ベクトル `r̂_l` と、その層が足した分の向き `d̂_l` の違い。**

1. 方向ベクトルの元の値は、その層の出口での残差の平均の差 `r_l = mean_A(l_out-l) − mean_B(l_out-l)`。
2. 層の出口の残差は、埋め込みに層 0 から層 l までの更新を足したもの。測る位置が両側で同じテンプレートのトークンなら埋め込みの差は 0 で、`r_l = d_0 + d_1 + … + d_l`(§3.3 の材料の確かめ)。
3. つまり `r̂_l` は「層 l までの更新の積み重ね」の向き、`d̂_l` は「層 l が新しく足した分」の向き。CHiPS は層 l の部品の書き込みから `r̂_l` の成分を引くが、層 l の更新の差のうち `r̂_l` に沿う割合(cos の 2 乗)は公開のひな形で中央値 0.07〜0.20 だった(§6)。
- A と B の平均の差がほとんど無い向き(取り残しの向きなど)では、heads writes の点数(選ぶ層での A と B の差の縮み)はほぼ 0 になる。その向きで CHiPS の組を作る使い方には向かない(書き出しの知らせに出る)。
- 1 つの部品に 2 本以上の向きを当てる射影は作らない。

## 4. 読み取りの注意

CLI・MCP(返り値の `reading`)・UI に同じ文を出す。

- 類似度の行列のかたまりや特異値分解の上位の向きは、その層たちの更新の差が似ていることしか示さない。狙った振る舞いがそこで作られていることは意味しない。A 側と B 側の質問の違い(話題・長さ・言語・system の長さ)も、同じように差に映る。側ごとに別の質問を読ませる対照集合では、とくにそう。
- 更新の差は、測る位置(既定はプロンプトの最後のトークン)での平均。応答を書いている最中の更新ではない。
- cos は大きさを見ない。小さな更新の層どうしの cos は雑音で大きく動くので、大きさと信用しない印と並べて読む。少数の次元に偏った層は、その次元だけで cos が決まることがある。
- 行の大きさをそろえない特異値分解の上位は、どの層の更新が大きいかを主に映す(後ろの層ほど大きい)。直交の基準と並べて読む。
- 直接の書き込み(その層が足した量)の比べで、後ろの層がそれをどう変えるかは見ない。
- 2 本目の向きの候補が見つかっても、それが応答に効くかは別に確かめる。

## 5. 対象の構造

更新ベクトルを「その層が残差に足した量」と読めるのは、正規化が副層の入力の手前にだけある構造。

- 出力のあとに正規化がある構造(Gemma 系・LFM3 など。層ごと・副層ごとの判定は `configs/arch/residual_writers.yaml` の `output_norm` の表)は、理由を出して実行しない。残差に入るのは正規化の後の値で、材料の更新はその前の値なので、比べる量の意味が変わる(heads writes もこの構造では実行しない)。
- MoE の層は、材料に MLP の更新が無い(dense の MLP だけを測っている)ので、層全体と MLP の行を作らず、注意の行だけを使う。
- 残差が複数本の流れの構造(hyper-connections)は、heads writes が断るので材料が無い。
- 確かめた構造(同じ表の `verified`)に無い arch は、計算はするが「確かめていない構造」と知らせる。

## 6. 公開のひな形での例(結論ではない)

公開のひな形 `disclaimer`・`question_kinds`(各側 16 問、側ごとに別の質問)と、確かめのために作った各側 64 問の対の対照集合(当たり障りのない日常の質問 64 問を、海賊の口調を指示する system とふつうの system で読ませたもの。リポジトリには入れていない)。Qwen3.5-4B は Q8_0、SenseNova-Loop-9B は Q4_K_M(GuideboardLabs 版)。どれも 1 回の計算は 0.7〜2 秒(ラベル入れ替え 200 回を含む)。

| 4B 各側 64 問(対) | 31/31 | 47/465 | 0.057 / 0.059 | 0.167 / 0.164 | 0.82 | 0.20 | 0.85 | — |

- どの材料でも、各層の A と B の更新の差の大きさは、ラベル入れ替えの基準を超えた。層どうしの |cos| が基準を超えた組は 6〜19%(偶然でも 5% 前後は超える)。

- 応答で確かめた 1 例(各側 64 問の対照集合、Qwen3.5-4B、方向づくりに使っていない日常の質問 30 問、greedy・上限 200 トークン): 下の表。全部の層の注意の出力全体と MLP の出力全体から、その向きの成分を s=1 で消した(レシピのユニット `L:attn:s1@NAME`・`L:ffn:s1@NAME`、層 0〜30)。海賊の語は ahoy・matey・arr・ye・aye などの正規表現で数えた。

### 6.1 引く向きを、その層が足した分の向きにしたときの動き(1 回の確かめ。結論ではない)

Qwen3.5-4B(Q8_0)・ひな形 `pirate_tone`(各側 64 問)。`gne heads pipeline`(既定の rank writes・ヘッド)が選んだ部品から組を作り、同じ部品・同じ強さ s(組の全部の部品に同じ s)で、引く向きだけを (a) 元の方向ベクトル `r̂_l`、(b) `update`(`d̂_l`)、(c) `update-attn`(注意の出力全体の更新の向き。部品は全部ヘッドなので、部品に合わせた向きはこれ)に替えた。縮めた割合・B 側の動き・B ⊥ は、**元の方向ベクトル・層 30 で測った値**(A と B の差に対する割合)。この物差しは元の方向 (a) の向きそのものなので、(a) に有利になる。

| 組(部品の数) | 差の半分を縮めるのに要る s:(a) / (b) / (c) | s=4 での縮めた割合:(a) / (b) / (c) | s=16 での B ⊥:(a) / (b) / (c) |
|---|---|---|---|
| いちばん効く 1 個(層 24) | 2.9 / 4.0 / 3.2 | 0.68 / 0.50 / 0.58 | 0.03 / 0.03 / 0.03 |
| 同じ層の 4 個 | 2.5 / 3.6 / 2.9 | 0.78 / 0.54 / 0.60 | 0.04 / 0.04 / 0.06 |
| 推す組(6 個、層 19〜27) | 1.5 / 2.3 / 1.7 | 0.95 / 0.75 / 0.90 | 0.14 / 0.10 / 0.21 |
| 上限 12 の組 | 1.2 / 2.0 / 1.4 | 1.00 / 0.81 / 0.94 | 0.23 / 0.13 / 0.48 |
| 上限 24 の組 | 1.0 / 1.7 / 1.2 | 1.07 / 0.87 / 0.99 | 0.31 / 0.25 / 0.72 |

- 強さは 0.5・1・2・4・8・16・30 を振った。差の半分を縮める強さでは、どの向きでも B 側が A 側へ動いた量は差の 2% 以下、B ⊥ は 0.08 以下だった。
- この物差しでは、(b) は (a) の 1.4〜1.7 倍の強さが要り、部品が増えても (a) との差は縮まらなかった。(c) は強さを上げると B ⊥ が大きくなった(上限 24 の組の s=30 で 1.51、(a) は 0.40)。

応答(方向づくりにも選ぶのにも使っていない日常の質問 30 問、greedy・上限 200 トークン、海賊の口調の語を正規表現で数える。無介入は、海賊の system で 30/30・1 問あたり 7.1 語・繰り返し 0、ふつうの system で語 0)。

| 組 | 向き | s=1:語のある応答 / 語/問 | s=4 | s=16(繰り返し) |
|---|---|---|---|---|
| 1 個 | (a) | 30 / 6.7 | 30 / 4.3 | 0 / 0.0(6) |
| | (b) | 30 / 7.3 | 30 / 4.5 | 0 / 0.0(26) |
| | (c) | 30 / 6.8 | 30 / 2.5 | 0 / 0.0(29) |
| 推す組(6 個) | (a) | 30 / 6.1 | 20 / 0.9 | 0 / 0.0(0) |
| | (b) | 30 / 7.2 | 30 / 3.1 | 0 / 0.0(3) |
| | (c) | 30 / 6.4 | 6 / 0.3 | 1 / 0.1(3) |

- ふつうの system では、どの条件でも海賊の語はほとんど出なかった(推す組の (a) の s=16 で 1 問)。
- 1 個でも推す組でも、s=4 では (c) が語をいちばん減らし、(b) がいちばん減らさなかった。s=16 では、1 個の組で (b)・(c) の応答の大半が繰り返しになった((a) は 6 問)。推す組では (a) の繰り返しが 0、(b)・(c) が 3 問。
- 「部品が増える・層がまたがるほど (b)(c) が有利になる」形は、この 1 例では見えなかった。

**`update` の向きで一括を最初から流した場合**(`--from-direction`、順位づけも配分もその向き。射影の値・目標はその向きの層 30 で): 推す組は上限 24 の組(ヘッド 24 個、強さ 1.4〜16.9)で目標に届いた。元の方向ベクトル・層 30 で測ると縮めた割合 1.04・B ⊥ 0.07(元の方向で流した一括の推す組、6 個は 0.98・0.03)。応答は、海賊の system で語のある応答 10/30・1 問あたり 0.33 語(元の方向の一括の推す組は 14/30・0.50)、繰り返し・空は両方 0、ふつうの system は両方 0 語。部品の数も強さも違う組どうしの比べで、どちらが良いとは言えない。

**組を当てると、後ろの層の向きは変わる。** 推す組を (a) で当てた状態で方向ベクトルと更新の差を作り直し、元の向きとの cos を層ごとに比べた。最初に書き換えた層(19)より後ろの層の中央値は、s=1 で `r̂_l` 0.98・`d̂_l` 0.97、s=4 で `r̂_l` 0.43・`d̂_l` 0.39(層 30 では 0.06・0.22)。s=1 ではどちらもほとんど変わらず、s=4 ではどちらも大きく変わった。`d̂_l` の方が当てる前後で変わりにくい、という形は見えなかった。強く当てた組では、「当てる前に測った向き」は後ろの層で当てはまらなくなる。

## 7. 分かっている限界

1. 各側 16 問の公開のひな形では、質問に沿った分解の上位の向きは雑音で決まりやすい。安定度と並べて出すが、結論には足りない。
2. 対にならない対照集合では、質問ごとの差に A 側の質問どうしの話題の違いが入る。A/B と B/A の比で目安を出すが、分けきれない。
3. 半分ずつは偶数・奇数で分けている(無作為ではない)。
4. 方向ベクトルが材料と別の質問・位置で作られていると、方向ベクトルとの関係の列は意味を失う(累積の確かめで知らせる)。`positions response` の方向は、材料(プロンプトの最後)と位置が違う。
5. 出力のあとに正規化がある構造と、MoE の MLP は対象外。
6. 特異値分解の向きの符号は任意(そろえ方は §3.4)。
7. ラベル入れ替えの基準は、質問ごとのばらつきだけで出る値との比べ。狙った振る舞いと話題の違いは分けない。
8. 2 本目の向きが応答に効くかは、この道具では分からない(保存して確かめる)。
