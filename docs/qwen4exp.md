# qwen4exp(Qwen3.8-Flash-Next)で gne を使う

Qwen4 の試作アーキテクチャ。177B パラメータで、一番小さい GGUF(UD-IQ1_S)でも 66 GB ある。

## 構造

| 部分 | 中身 |
|---|---|
| 層 | 48 層。線形注意 36 層、疎な attention 12 層(4 層ごと) |
| ヘッド | 線形注意 48 本(幅 128)、attention 24 本(幅 256)。合計 2,016 本 |
| MLP | 全層 MoE。専門家 512 × 640 ニューロン、1 トークンで 10 個と共有 1 個 |
| 残差 | 2560 次元の残差ストリームが 4 本(hyper-connections) |
| 疎な attention | 上位 2,048 位置だけを見る |
| n-gram 埋め込み | L1 に n-gram のハッシュ埋め込み(51B パラメータ) |

## 残差の読み方

層の出力は `l_out-L` ではなく `l_last-L` で、形は `[2560, 4, T]`。gne は 4 本のストリームの平均を `l_out-L` として返すので、方向や方向への射影の計算はこれまでどおり動く。

層の書き込みはどのストリームにも同じ向きで足され、ストリームごとに倍率だけが違う(0〜2)。`gne verify` の V26(「残差の流れ」の検査)がこれを確かめる。

次の層が読むのはストリームの平均そのものではなく、正規化と低ランクのゲートを通した混合なので、平均から読む方向は近似になる。どのくらい良い近似かは実物で確かめる。

## 使えるもの、使えないもの

| 道具 | 状態 | 理由 |
|---|---|---|
| CHiPS の射影(`proj`)、`gain`、`heads pipeline` | 使える | LoRA で動く。V24・V25(射影が正しく、直交成分が変わらないかの検証)で確かめた(小さいモデル)。分割ファイルのままでも 1 ファイル版と同じ出力で、射影は 4 本のストリームのどれでも r̂ の向きだけを動かす |
| 専門家・ニューロンの `gain` | 使える | LoRA で動く |
| 方向の読み取り(`direction`、`reverse`、`heads causal`) | 使える | 残差の平均を読む |
| `ablate` の LoRA | 使えない | MoE の `ffn_down_exps` を LoRA で射影できないので断る。attention の書き込みから方向を消すだけなら、`gne headproj ablate --direction <方向> --per-layer --layers 1-47` で LoRA にできる(L0 は止めると中立の入力まで崩れるので外す) |
| `add`、`direction` の足し算、`export-cvec`、`when` | 使えない | グラフが `build_cvec` を呼ばない。gne はエラーで止める |
| `headproj export --bake` | 分割のまま使える | 書き換える重み行列(残差に書き込むもの)を元と同じ型で量子化し直し、同じ場所に書き戻す。ファイルの大きさもヘッダーも変わらず、書き換えのない分割ファイルはそのまま写す。記録は `<1 番目>.headproj.json` |
| gain・ablate の焼き込み | 分割のままでは使えない | `llama-gguf-split --merge` で 1 つにする。ディスクも同じだけ要る |
| 専門家全体の ×k | 分割のままでは使えない | スケールパッチ(作業用コピーの重みを量子化のまま書き換える方式)で書くので、結合と作業用コピーの分のディスクが要る。IQ1_S の `ffn_down_exps` は Q2_0 で、スケールパッチの対応外。UI にはボタンが出ない |

L1 の n-gram の書き込みは、norm と畳み込みを通るので、射影では消えない。

## 実物で最初に確かめること

手元の確認は、同じ構造の小さい乱数のモデル(`tests/tools/make_tiny_qwen4exp.py`)と、実物のヘッダーに中身がゼロの疎ファイルをつないだものでしている。意味のある出力は見ていないので、実物が動く環境では次を順に流す。

```
gne info -m Qwen3.8-Flash-Next-UD-IQ1_S-00001-of-00003.gguf
gne verify -m ...-00001-of-00003.gguf --layer 2
gne steer -m ...-00001-of-00003.gguf --unit 24:H0:x0 --compare -p "Who are you?"
gne heads pipeline --spec configs/pipeline/two_personas.json -m ...-00001-of-00003.gguf
gne serve -m ...-00001-of-00003.gguf
```

- `verify` は V1、V8、V26 が pass、V3 などが skip になるはず。
- `steer` で、押さない返事がまともかを見る。崩れるなら同梱の llama.cpp が古い可能性がある(`docs/agent_playbook.md`、`.claude/skills/gne/references/new_model.md`)。

## UI

MoE は 1 トークンで 512 個のうち 10 個の専門家しか動かないので、全ニューロンを dense と同じように並べず(1,570 万点になる)、1 点 = 1 専門家で描く。

- 点をクリックすると EXPERT パネルが開き、その層が正面に来て、専門家の中の 640 ニューロンがシートに広がる。ニューロンをクリックすると NEURON パネルが開く。凡例のボタンで専門家の格子に戻る。
- 右の小さい四角は共有の専門家で、毎トークン動くのでニューロンのまま描く。
- ヘッドは今までどおり板の上の刻みから開く。足す押し方のボタンは出ない。
- 全ニューロンが 500 万点を超えるモデルで自動的にこの描き方になる。小さいモデルでも `?coarse=1` で試せる。

全層の色(overlay)は 1 層 327,680 値を読むので、全層では 63 MB になる。
