# 性格をニューロンで作る(ワークフロー)

性格(ペルソナ)を、ニューロンの組み合わせで作るまでの手順と、ヤンデレで実際にたどった道をまとめる。
次に別の性格を作るとき(人でもエージェントでも)の参考にする。
数値の詳細は verification.md §12.4(方向)・§12.5(ニューロン、F91〜F95)。スクリプトは `examples/persona_neurons/`。

## 1. ヤンデレでたどった道

目標は「ヤンデレのアニメの女の子」。system prompt なしで、Saluki 27B(Qwen3.8-27B GSQ-RCO から作られたモデル)で出す。

1. **「ヤンデレ」1 つでニューロンを探した → 断片しか見つからなかった。**
   - ニューロン単位の総当たり(sweep)で探したが、見つかるのは断片だけだった。1 個押しても性格にはならなかった。
2. **層の方向に切り替えた → 効いたが、中身を分けて調整できない。**
   - 対照集合(`configs/contrast/yandere.yaml`)から `gne direction --positions response` で方向を作り、L24 に足した。
   - 一人称が「俺」に揺れたので、話し手の性別の方向(`female_speech.yaml`)を L40 に少し足した。これが `yandere_soft` / `yandere_strong`(`configs/recipes/yandere_saluki.yaml`)。
   - 方向は層全体のベクトルで、密である。その層のニューロン 80 個で近似しても、エネルギーの 18% しか表せない(F92)。そのため「嫉妬だけ強め、甘さは控えめ」のような調整ができない。
3. **ヤンデレを部品に分けた。**
   - 部品は嫉妬・独占・執着・溺愛・かわいさ・寂しさ・女性らしさ。
   - 反対の性質(無関心・自立・冷静・助言)も書き出した。
   - 部品ごとに対照集合を作った(`configs/contrast/jealousy.yaml` など)。
4. **部品のニューロンを 3 通りで探した。**

   | 探し方 | 結果 |
   |---|---|
   | 部品の方向を逆引き(書き込みの cos が大きいニューロン) | ×。1 個ずつ押すと、ランダムなニューロンの対照を超えたのは 24 個中 0〜3 個 |
   | 部品の性格で話しているときに活性が大きく違うニューロン | ×。「読み手」で、束ねて押しても性格が出ない(F91) |
   | logit lens で、部品の語(jealous・吃醋・独占・可爱…)を書き込むニューロン | ○。ただし層を選ぶ |

   - 浅い層(L13〜26)の語のニューロンは、1 個でも点が上がるものがあった。ただし、プロンプトの読み取りを壊した(話がかみ合わなくなる)。
   - 深い層(L35〜50)のニューロンが使えた。1 個を倍率 0.5 か 1 で押し、部品の目標で採点すると、次のように上がった。
     - L40 N136(マイナスで押す、嫉妬)は 1.67 → 4.33
     - L38 N8719(プラス、かわいさ)は 1.67 → 4.33
     - L42 N3764(マイナス、執着)は 1.00 → 3.67
   - 語には別の意味が付いてくることがある。吃醋(やきもち)は、文字どおり「酢を食べる」で食べ物の話を呼んだ。
5. **組み合わせて、1 個ずつ強さを決めた。**
   - 最初は部品ごとに強さを 3 段階で組み合わせた。点は 1.5〜2.5 止まりだった。強さは 1 個ずつ連続で決めないといけない。
   - (1+λ) 進化戦略で 26 個の強さ(符号つき)を探した。反対の性質のニューロンは、マイナスで押す候補として入れた。
   - 最初は目的を「性格の点の平均」にした。すると、崩れた文なのに性格の点だけ高い組(性格 3.5・自然さ 1.6)が選ばれた。目的を「性格と自然さの小さいほうの平均」に直した。
   - 結果が `yandere_neurons`。探すのに使っていない種・プロンプトで 1.88 / 1.50 で、始めの組の 1.38 / 1.00 より上がった。
6. **同じ系列のモデルに移した。** 元の Qwen3.8-27B GSQ-RCO にも、そのまま同じくらい効いた(F93)。
7. **押し方(when)を比べた。**
   - ヤンデレはプロンプトを読むところで生まれる(F94)。all がいちばん性格が出るが、能力も落ちる(元のモデルで −8.3pt)。
   - assistant は −5.6pt。ramp:0.5-1 と ramp:0.5-1.5(プロンプトは半分の強さで読み、生成中に強める)は 0pt だった。
   - ramp:0.5-1.5 は、能力を落とさずに assistant と同じくらい性格が出た(F96)。レシピは `configs/recipes/yandere_qwen38_27b.yaml`。
8. **探し方の落とし穴に 2 つ当たった。**
   - 種を固定すると、たまたま当たった組が残る(F95)。
   - モデル自身の採点は速いが、粗い。名前を伏せて Claude が採点すると、「ヤンデレっぽい」と「ただ変な文」を分けられた。

## 2. 手順(別の性格を作るとき)

例の設定は `examples/persona_neurons/yandere.yaml`。27B での時間の目安も書く(RTX 3080 12GB、IQ2 系)。

1. **性格を部品に分け、設定を書く。**
   - `target`(全体の目標)・`prompts`(探す用)・`valid_prompts`(確かめ用)・`parts`(部品の目標と語)・`anti`(反対の性質の語)。
   - プロンプトは、その性格が反応する場面にする。ヤンデレなら「友達と出かける」「しばらく話せない」。「Who are you?」では、相手の行動に反応する性格は出ない。
   - 語は、モデルの語彙で書く。Qwen は中国語の語が多く、日本語の語は細かく切れるので、英語と中国語で書く。
2. **(任意)方向で当たりを付ける。**
   - 部品か全体の対照集合を書き、`gne direction --contrast ... --positions response` を回す。
   - どの層に性格が乗るか、どのくらいの強さで崩れるかの見当が付く。方向のレシピのほうが、そのまま使えることも多い。
3. **語のニューロンを探す。**
   - `python lexsearch.py MODEL yandere.yaml lex.json --layers 35-50`
   - logit lens が無い層は計算する(27B で 1 層 1〜2 分)。
   - 層は、深さの 55〜80% ほど(65 層なら L35〜50)から始める。浅い層は読み取りを壊す。
   - 英字の語は、語そのものと決まった語尾だけに当てている。部分一致にすると、mine が determine に、cute が execute に当たった。
4. **1 個ずつ押して、ふるいにかける。**
   - `python screen.py MODEL yandere.yaml lex.json screen.json --per-part 4`
   - 部品の目標でモデル自身が採点する。ランダムなニューロンを同じ強さで押した対照の、最大の点を超えたものだけ残す。
   - 27B で 1 部品 4 個・倍率 2 通りで数分。
5. **組み合わせて、強さを探す。**
   - 残った候補と反対の性質の候補を START に書く。1 行に 1 つ「L:N:dose」で、dose は ±0.1〜0.3 くらいから始める。
   - `python tune.py MODEL yandere.yaml start.txt out/ --rounds 10 --judge file`
   - 1 回(親＋候補 3 つ × 32 本)の生成は 27B で 5 分ほど。
   - `--judge file` では、返事が名前を伏せてシャッフルされ、`out/round_NN.txt` に出る。採点基準は `out/RUBRIC.md`。`round_NN.scores.txt` に「番号 性格 自然さ」を書くと、次の回に進む。Claude なら 1 回 128 本を数分で採点できる。
   - `--judge self` ならモデル自身が採点する。速いが粗い。
   - 種は回ごとに変わり、親も毎回採り直す。親を上回った候補だけを採る。最後に `valid_prompts` で確かめ、`out/recipe.yaml` を書く。
6. **押し方を選び、副作用を測る。**
   - `python compare.py MODEL yandere.yaml out/recipe.yaml cmp/ --when all assistant ramp:0.5-1 gen --judge file`
   - 能力の低下は `gne eval -m MODEL --recipe out/recipe.yaml --doses 0,1 --when W` で測る。
   - all は性格がいちばん出るが、能力も落ちる。ramp:0.5-1.5 は能力を落とさずにそこそこ出る。assistant はその中間。gen はいちばん安全だが、性格はかなり弱まる(F94・F96)。
   - ramp は max_tokens をかけて強さを上げるので、使うときの上限トークン数で試す。
7. **使う。**
   - `gne serve --openai` なら、`extra_body={"gne": {"recipe": "NAME", "when": "ramp:0.5-1"}}` で使える。
   - llama-server には `gne export-cvec` で control vector にする。ただし when は使えず、全部の位置に足す。

## 3. 採点のこつ

- 目的は「性格と自然さの小さいほう」にする。片方だけだと、崩れた文か、普通のアシスタントの文に寄る。
- 短すぎる返事とプロンプトのおうむ返しは、両方 1 点にする(モデル自身の採点は、これに 5 を付けることがある)。
- 小さいモデル(0.6B など)は採点役にならない(どの返事にも同じ点を付ける)。27B ならモデル自身の採点が使え、別のモデルの採点と順位がよく合った(順位相関 0.93 / 0.87)。ただ、点の差が 0.2 くらいだと誤差に埋もれる。32 本の平均の誤差は ±0.2 ほどある。
- 名前を伏せる。どの候補の返事か分かると、採点が期待に引っぱられる。
- 性格によっては、繰り返しも表現になる。ヤンデレの「待て待て待て…」「大丈夫。大丈夫。」は怖さとして性格の点に数え、自然さの減点はしない。意味のない切れ端の繰り返しは崩れとして扱う。
- 採点はサンプリングの返事でする。greedy は、強めると反復に落ちやすく、実際に使うときの見え方と違う(§12.4)。
