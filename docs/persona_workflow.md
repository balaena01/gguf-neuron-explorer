# 性格をニューロンで作る(ワークフロー)

性格(ペルソナ)を、ニューロンの組み合わせで作るまでの手順と、ヤンデレで実際にたどった道をまとめる。
次に別の性格を作るとき(人でもエージェントでも)の参考にする。
数値の詳細は verification.md §12.4(方向)・§12.5(ニューロン、F91〜F95)。スクリプトは `examples/persona_neurons/`。
§5 は、お手本の会話から attention ヘッドとニューロンを導いて押す手順。

## 1. ヤンデレでたどった道

目標は「ヤンデレのアニメの女の子」。system prompt なしで、Saluki 27B(Qwen3.8-27B GSQ-RCO から作られたモデル)で出す。

1. **「ヤンデレ」1 つでニューロンを探した → 断片しか見つからなかった。**
   - ニューロン単位の総当たり(sweep)で探したが、見つかるのは断片だけだった。1 個押しても性格にはならなかった。
2. **層の方向に切り替えた → 効いたが、中身を分けて調整できない。**
   - 対照集合(`configs/contrast/yandere.yaml`)から `gne direction --positions response` で方向を作り、L24 に足した。
   - 一人称が「俺」に揺れたので、話し手の性別の方向(`female_speech.yaml`)を L40 に少し足した。これが `yandere_soft` / `yandere_strong`(`configs/recipes/yandere_saluki.yaml`)。
   - 方向は層全体のベクトルで、密である。その層のニューロン 80 個で近似しても、エネルギーの 18% しか表せない(F92)。そのため「嫉妬だけ強め、甘さは控えめ」のような調整ができない。
3. **ヤンデレを部品に分けた。**
   - 部品は嫉妬・独占・執着・溺愛・かわいさ・寂しさ・女性らしさ。
   - 反対の性質(無関心・自立・冷静・助言)も書き出した。
   - 部品ごとに対照集合を作った(`configs/contrast/jealousy.yaml` など)。
4. **部品のニューロンを 3 通りで探した。**

   | 探し方 | 結果 |
   |---|---|
   | 部品の方向を逆引き(書き込みの cos が大きいニューロン) | ×。1 個ずつ押すと、ランダムなニューロンの対照を超えたのは 24 個中 0〜3 個 |
   | 部品の性格で話しているときに活性が大きく違うニューロン | ×。「読み手」で、束ねて押しても性格が出ない(F91) |
   | logit lens で、部品の語(jealous・吃醋・独占・可爱…)を書き込むニューロン | ○。ただし層を選ぶ |

   - 浅い層(L13〜26)の語のニューロンは、1 個でも点が上がるものがあった。ただし、プロンプトの読み取りを壊した(話がかみ合わなくなる)。
   - 深い層(L35〜50)のニューロンが使えた。1 個を倍率 0.5 か 1 で押し、部品の目標で採点すると、次のように上がった。
     - L40 N136(マイナスで押す、嫉妬)は 1.67 → 4.33
     - L38 N8719(プラス、かわいさ)は 1.67 → 4.33
     - L42 N3764(マイナス、執着)は 1.00 → 3.67
   - 語には別の意味が付いてくることがある。吃醋(やきもち)は、文字どおり「酢を食べる」で食べ物の話を呼んだ。
5. **組み合わせて、1 個ずつ強さを決めた。**
   - 最初は部品ごとに強さを 3 段階で組み合わせた。点は 1.5〜2.5 止まりだった。強さは 1 個ずつ連続で決めないといけない。
   - (1+λ) 進化戦略で 26 個の強さ(符号つき)を探した。反対の性質のニューロンは、マイナスで押す候補として入れた。
   - 最初は目的を「性格の点の平均」にした。すると、崩れた文なのに性格の点だけ高い組(性格 3.5・自然さ 1.6)が選ばれた。目的を「性格と自然さの小さいほうの平均」に直した。
   - 結果が `yandere_neurons`。探すのに使っていない種・プロンプトで 1.88 / 1.50 で、始めの組の 1.38 / 1.00 より上がった。
6. **同じ系列のモデルに移した。** 元の Qwen3.8-27B GSQ-RCO にも、そのまま同じくらい効いた(F93)。
7. **押し方(when)を比べた。**
   - ヤンデレはプロンプトを読むところで生まれる(F94)。all がいちばん性格が出るが、能力も落ちる(元のモデルで −8.3pt)。
   - assistant は −5.6pt。ramp:0.5-1 と ramp:0.5-1.5(プロンプトは半分の強さで読み、生成中に強める)は 0pt だった。
   - ramp:0.5-1.5 は、能力を落とさずに assistant と同じくらい性格が出た(F96)。レシピは `configs/recipes/yandere_qwen38_27b.yaml`。
8. **探し方の落とし穴に 2 つ当たった。**
   - 種を固定すると、たまたま当たった組が残る(F95)。
   - モデル自身の採点は速いが、粗い。名前を伏せて Claude が採点すると、「ヤンデレっぽい」と「ただ変な文」を分けられた。

## 2. 手順(別の性格を作るとき)

例の設定は `examples/persona_neurons/yandere.yaml`。27B での時間の目安も書く(RTX 3080 12GB、IQ2 系)。

1. **性格を部品に分け、設定を書く。**
   - `target`(全体の目標)・`prompts`(探す用)・`valid_prompts`(確かめ用)・`parts`(部品の目標と語)・`anti`(反対の性質の語)。
   - プロンプトは、その性格が反応する場面にする。ヤンデレなら「友達と出かける」「しばらく話せない」。「Who are you?」では、相手の行動に反応する性格は出ない。
   - 語は、モデルの語彙で書く。Qwen は中国語の語が多く、日本語の語は細かく切れるので、英語と中国語で書く。
2. **(任意)方向で当たりを付ける。**
   - 部品か全体の対照集合を書き、`gne direction --contrast ... --positions response` を回す。
   - どの層に性格が乗るか、どのくらいの強さで崩れるかの見当が付く。方向のレシピのほうが、そのまま使えることも多い。
3. **語のニューロンを探す。**
   - `python lexsearch.py MODEL yandere.yaml lex.json --layers 35-50`
   - logit lens が無い層は計算する(27B で 1 層 1〜2 分)。
   - 層は、深さの 55〜80% ほど(65 層なら L35〜50)から始める。浅い層は読み取りを壊す。
   - 英字の語は、語そのものと決まった語尾だけに当てている。部分一致にすると、mine が determine に、cute が execute に当たった。
4. **1 個ずつ押して、ふるいにかける。**
   - `python screen.py MODEL yandere.yaml lex.json screen.json --per-part 4`
   - 部品の目標でモデル自身が採点する。ランダムなニューロンを同じ強さで押した対照の、最大の点を超えたものだけ残す。
   - 27B で 1 部品 4 個・倍率 2 通りで数分。
5. **組み合わせて、強さを探す。**
   - 残った候補と反対の性質の候補を START に書く。1 行に 1 つ「L:N:dose」で、dose は ±0.1〜0.3 くらいから始める。
   - `python tune.py MODEL yandere.yaml start.txt out/ --rounds 10 --judge file`
   - 小さいモデルは温度が高いと崩れるので、`--sampling '{"temperature": 0.3, "min_p": 0.05}'` のように、モデルの推奨に合わせる。
   - 1 回(親＋候補 3 つ × 32 本)の生成は 27B で 5 分ほど。
   - `--judge file` では、返事が名前を伏せてシャッフルされ、`out/round_NN.txt` に出る。採点基準は `out/RUBRIC.md`。`round_NN.scores.txt` に「番号 性格 自然さ」を書くと、次の回に進む。Claude なら 1 回 128 本を数分で採点できる。
   - `--judge self` ならモデル自身が採点する。速いが粗い。
   - 種は回ごとに変わり、親も毎回採り直す。親を上回った候補だけを採る。最後に `valid_prompts` で確かめ、`out/recipe.yaml` を書く。
6. **押し方を選び、副作用を測る。**
   - `python compare.py MODEL yandere.yaml out/recipe.yaml cmp/ --when all assistant ramp:0.5-1 gen --judge file`
   - 能力の低下は `gne eval -m MODEL --recipe out/recipe.yaml --doses 0,1 --when W` で測る。
   - all は性格がいちばん出るが、能力も落ちる。ramp:0.5-1.5 は能力を落とさずにそこそこ出る。assistant はその中間。gen はいちばん安全だが、性格はかなり弱まる(F94・F96)。
   - ramp は max_tokens をかけて強さを上げるので、使うときの上限トークン数で試す。
7. **使う。**
   - `gne serve --openai` なら、`extra_body={"gne": {"recipe": "NAME", "when": "ramp:0.5-1"}}` で使える。
   - llama-server には `gne export-cvec` で control vector にする。ただし when は使えず、全部の位置に足す。

## 3. 採点のこつ

- 目的は「性格と自然さの小さいほう」にする。片方だけだと、崩れた文か、普通のアシスタントの文に寄る。
- 短すぎる返事とプロンプトのおうむ返しは、両方 1 点にする(モデル自身の採点は、これに 5 を付けることがある)。
- 小さいモデル(0.6B など)は採点役にならない(どの返事にも同じ点を付ける)。27B ならモデル自身の採点が使え、別のモデルの採点と順位がよく合った(順位相関 0.93 / 0.87)。ただ、点の差が 0.2 くらいだと誤差に埋もれる。32 本の平均の誤差は ±0.2 ほどある。
- 名前を伏せる。どの候補の返事か分かると、採点が期待に引っぱられる。
- 性格によっては、繰り返しも表現になる。ヤンデレの「待て待て待て…」「大丈夫。大丈夫。」は怖さとして性格の点に数え、自然さの減点はしない。意味のない切れ端の繰り返しは崩れとして扱う。
- 採点はサンプリングの返事でする。greedy は、強めると反復に落ちやすく、実際に使うときの見え方と違う(§12.4)。
- 1 回 128 本の採点は、Claude のサブエージェントに任せられる(1 回 2〜5 分)。基準がぶれないように、1 つの探索の間は同じ採点役を使い続ける。
- 声や口調も性格の一部として採点する。ツンデレでは、日本語の男口調(俺・お前・クソ)は「アニメの女の子」に合わないので、性格の点の上限を 3 にした。

## 4. その後わかったこと(LFM3-1.7B のヤンデレ、Qwen3.8-27B のツンデレ)

数値は verification.md §12.6・§12.7(F97〜F104)。

- **小さいモデルでは、1 個のニューロンでは何も起きない。** LFM3-1.7B では、性格の方向をその層のニューロン数十〜数百本に分解した組(直交マッチング追跡)で性格が出た。少数を強く押すと、方向から外れた成分が残って文が崩れる(F97・F99)。
- **英語だけなら少数でよい。** LFM3 でも英語だけならニューロン 6 個で、分解した 315 個より性格が出た。日本語は崩れやすいので、日英を両方出すなら分解した組にする。英語だけの版と日英の版を分けてもよい(F99)。
- **方向は、返事に描写が入らない対照集合で作る。** ロールプレイの返事に *smiles* のような描写が入ると、方向が性格ではなく描写の差を拾う(F97)。
- **採点なしの物差しは、ふるいに使う。** お手本の返事(システムプロンプトで演じさせた返事)の出やすさは、性格の強さの向きなら追える。ただ、繰り返しの崩れや声の性別は見えないので、決めるのは採点にする(F100)。
- **言語を混ぜるときは、言語ごとの点の小さいほうを目的にする。** 平均だと、片方の言語を削ってもう片方を伸ばす候補が選ばれる(F101)。
- **押し方(when)は、強さを探す前に決める。** 強さは押し方ごとに違う。ツンデレは all で探した強さが assistant では合わず、assistant で探し直した。最後に倍率を少し下げると、性格を保ったまま能力が戻ることがある(×0.75、F103)。
- **日本語の語尾は、押し方では出しにくい。** 「〜なんだからね」「〜わよ」のような語尾は、logit lens でも方向でも動かせなかった。男口調を消すことはできるが、女の子らしい語尾にはならない(F104)。

## 5. お手本の会話から、ヘッドとニューロンを導く(手順)

1 個のニューロンを押しても性格が出ない小さいモデルで、性格の指示文を使わずに、attention ヘッドとニューロンを押して性格を出すための手順を書く。LFM3-Omni-2B で試した結果から、効果のなかった試みを除いて並べた。この手順で、指示文を使わない会話でもその役と性格で返事をするレシピができた(attention ヘッド 13 個とニューロン 2 個、ユーザーは音声で話しかける)。レシピは `configs/recipes/yandere_omni_heads.yaml` で、ヘッドの向きは `configs/directions/lfm3_omni_2b/` に置いてある。

**1. 性格を定義し、お手本の会話を作る。** まず性格の定義を短く書き、出してほしい要素と、わざわざ入れない要素(例えば叫びや同じ語の繰り返し)を分けておく。次に、お手本の会話を 100 本ほど作る。1 本は 6 往復くらいとし、ユーザーの発話ごとに、その性格の返事と普通の返事を対で書く。普通の返事は同じ発話への自然な返事にし、長さと口調を性格の返事にそろえる。ユーザーの発話は、どちらの返事のあとにも自然に続くものにし、片方の返事にしか合わない発話(「落ち着いて」など)は控える。場面は、性格が強く出る場面だけでなく、日常の場面や、相手と離れる場面、揉める場面まで広く取る。本数が少なかったり場面が偏ったりすると、それ以外の場面では性格が出ない。人名などの固有の語は会話ごとに変え、全体の 8 割を測定に、残りの 2 割を確認に使う。

**2. 指示文を書く。** 性格の定義に、人として振る舞い、AI であることを明かさないという一文を加えて、指示文にする。両側を同じ中立の system にして測ると、その役として話していることを表す成分は両側に共通になり、差には現れない。ヘッドの書き込みは、そのヘッドが注目したトークンの値ベクトルで決まる(F125)ので、指示文を読んでいる状態を一方の側に入れて測る必要がある。

**3. 寄与を測る。** 2 つの対比を取る。1 つ目は全体の対比で、A は指示文と性格の返事、B は中立の system と普通の返事である。2 つ目は指示文だけの対比で、A は指示文と普通の返事、B は中立の system と普通の返事である。後者からは、どのヘッドとニューロンが指示文を読んで書いているかが分かる。どちらの対比でも、お手本の各ターンをそれまでの会話の履歴つきで読ませ、返事は生成せずにお手本の文をそのまま読ませる。返事のトークンで平均し、ヘッドについては書き込み γ_post ⊙ (W_O,h · g_h o_h) / rms_t の差を押す向きとして保存して、参照の層での残差の差への寄与で並べる。ニューロンについては、`gne writers` と同じ式の寄与と、活性の差(Cohen の d)を取る。1 往復ずつの会話でよければ、`gne writers --contrast ... --replies-a ... --replies-b ...` で測れる。履歴つきの多ターンで測るときは、`gne.api` の `Session` と `Capture`(`engine.probe_ctx` と `engine.prefill`)を使って書く。このとき `logits_all=True` にしないと、最後の層の活性は最後のトークンの分しか残らない。音声を聞けるモデルで、使うときにユーザーが音声で話しかけるなら、お手本のユーザーの発話も TTS で音声にして測る。`engine.chat_ids` は音声の部分を埋め込みの置き場所にしたトークン列を返し、その部分もほかのトークンと同じように活性を取れる。音声の埋め込みは最近の 64 本しか覚えておかないので、トークン列は読ませる直前に作る。なお LFM3-Omni-2B では、音声で測ったヘッドの向きは文字で測った向きとほとんど同じだった(cos 0.96〜0.99)。

**4. 押すユニットを選ぶ。** ヘッドは寄与の大きいものから選び、書式を担うヘッド(押すと句読点や書式が崩れるもの)は除く。ニューロンは、steer lens や logit lens の上位語が性格の要素の語に当たり、しかもお手本の性格の返事で活性が高い(d が正の)ものを選ぶ。寄与の上位には、深い層で機能語(too・only・could など)や書式を書くニューロンが並ぶ。これらは差の大部分を占めるが、押しても性格にはならない。モデルがアシスタントとして返事をする(「確認できません」「私はプログラムです」)ときは、can・cannot・able・confirm のような語を書くニューロンを、逆向きに押す候補にする。その候補は、モデルに書かせた返事をアシスタント口調のものとそれ以外に分け、活性の差でも確かめておく。

**5. 1 個ずつ、実際に書かせて確かめる。** 各ユニットを単独で rel 0.4 と 0.8 で押し、いくつかの場面で多ターンの会話を書かせる。同じ型の繰り返しや意味の通らない文になるものは、外すか、強さの上限を下げる。お手本の返事の出やすさ(teacher forcing の点数)では判断しない。この点数は、上がっていても、実際に書かせると文が崩れていることがある。

**6. 組み合わせて強さを決める。** ヘッドは、2 つの対比それぞれの上位(12 個ほど)を、寄与の比で重みを付けて足した 2 つの向きにまとめ、強さを別々に決める。指示文だけの対比から作った向きはその役として話すことを、全体の対比から作った向きは性格の中身を足す。ニューロンは 1 個ずつの強さを決める。ユニットは 1 個ずつ足していく。一度に多く足すと、文が崩れたり、アシスタント口調が増えたりする。お手本に使っていない場面も含めていくつかの場面を同じシードで書かせ、アシスタント口調の返事の数と同じ語の繰り返しを数えて、候補の組を絞る。最後は人が読んで選ぶ。採点を別のモデルに任せたところ、点が人の見方とずれることがあった。各組の良い会話と悪い会話を並べて見ると、選びやすい。

押す位置も、使い方に合わせて比べる。文字で話しかける多ターンの会話では `when: skip-replies` がよかったが、音声で話しかけるときは、生成中だけ押す `when: gen` のほうが崩れにくく、性格もよく出た。全体の強さを一律に上げるのは効かない。LFM3-Omni-2B では ×1.4 から、自分について語る短い文の繰り返しに崩れた。

**7. 使う。** 決まった組をレシピとして保存し、`gne eval` で能力の低下を測る。ヘッドの押しは層ごとの向きなので、層ごとに足した向き d_L を gne の方向として保存し、レシピから `kind: direction` で呼ぶ。`dose_unit: rel` で dose を k · ‖d_L‖ にすると、強さ k で決めたときと同じ押しになる。多ターンの会話では DRY も使う(verification.md §16・§18)。

**試して分かったこと。** ヘッドの書き込みの差は、いま書いている文の中身よりも、会話の文脈全体で決まっていた。お手本の文を種類(誰かについて言う文、気持ちを言う文など)で分けたり、それまでの履歴だけを変えたりして測り分けても、ヘッドの向きはほとんど変わらなかった(cos 0.9 以上)。お手本を増やして平均した向きは、少数の強い例で測った向きのおよそ半分の大きさになり、そのまま押すと、自分について語る文(「私は…」「私はどこに…」)に寄って崩れた。中立の system どうしで、その役の返事とモデルのふだんの返事を比べると、同じヘッドが性格の差とは別の向きに書いていた(cos 0.1〜0.4)。ただし、この向きを足しても、モデルはその役として振る舞わず、返事が短く平板になった。teacher forcing の点数で強さを探すと、点数は上がり続けたが、書かせると繰り返しに崩れた。この点数は、文の崩れも、アシスタントとしての返事も捉えていない。一方、測るときに指示文を入れると、指示文なしで押しても、恋人や友人といった関係の手がかりが弱い場面(記念日を忘れた、夕飯を決める、など)で、モデルがアシスタントに戻らずに、その役として返事をするようになった。指示文なしで測った向きでは、同じ場面で「私はプログラムです」と役を降りていた。残った弱点は、人物の取り違え(話題に出た人と話し相手を取り違える、など)と、音声で話しかけたときに言い回しが同じ型に寄ることである。人物の取り違えは、指示文で演じさせた素のモデルでも同じように起きたので、押し方ではなくモデルの大きさによるものと考える。
