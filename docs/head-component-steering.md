# CHiPS(Causal Head-isolated Projection Steering)— 方向成分だけを変えるヘッド介入

この手法を CHiPS と呼ぶ。Causal = 止めて測って効くヘッドを選ぶ、Head-isolated = 選んだヘッドの書き込みだけに限定する、Projection = 方向に沿った成分だけを動かす、Steering = それで振る舞いを変える。一番の特徴は、選んだヘッドだけに限定して射影すること(小文字の i の isolated)。

任意の「振る舞いの方向」について、**因果で効くヘッドを少数選び、そのヘッドが書くベクトルのうち方向成分だけを変える**手法。ペルソナ、口調、言語混入、冗長さ、迎合などに使える。

- 位置づけ: 全層の全書き込みに一律の射影を当てる方式(§6)と、ヘッドの出力を丸ごと倍率で変える方式(§5)の中間。**どこに当てるかを因果で測って決め、どう変えるかを方向成分に絞る**。
- 前提: 対象モデルで `gne direction` 相当の方向が作れること、ヘッド単位の捕捉と介入ができること(gne では §9 のコマンド)。

---

## 1. 考え方

attention ヘッドは毎トークン、残差と同じ次元のベクトルを残差に足している。このベクトルを 2 つに分ける。

- **方向成分**: 狙った振る舞いの向き `r̂` に沿った部分。「その振る舞いの側にどれだけ押しているか」
- **直交成分**: それ以外。話題、文法、次に来る語など、狙いと関係のない情報

直交成分には一切触らず、方向成分だけを強さ `s` で変える。

```
新しい書き込み = 元の書き込み − s × (元の書き込みのうち r̂ に沿った成分)
```

| s | 効果 |
|---|---|
| 0 | 変化なし |
| 1 | そのヘッドは `r̂` 方向に何も書かなくなる |
| 2 | 方向成分がちょうど反転する |
| > 2 | 反転した成分がさらに大きくなる |

`s` は**ヘッドごとに違う値**を割り当てる(§3.6)。

**入力依存性が自然に出る**のが要点。変化量は「そのヘッドがその入力で `r̂` 方向にどれだけ書いているか」に比例する。狙った状況では大きく変わり、それ以外ではほとんど変わらない。重みは 1 つしかないのに、「その振る舞いを書いているときだけ効く」動きになる。

## 2. 式と重みへの書き方

ヘッド `h` の書き込み行列(普通の attention なら `W_O` = `attn_output`、線形注意なら `ssm_out`)の、そのヘッドの列ブロックだけを書き換える。

```
W_O[:, blk_h]  →  W_O[:, blk_h] − s_h · r̂ r̂ᵀ W_O[:, blk_h]
```

`r̂ r̂ᵀ W_O[:, blk_h]` は「そのヘッドが書くベクトルのうち `r̂` に沿った部分を取り出す」計算。

**LoRA にすると層ごとに階数 1**。同じ層のヘッドが同じ `r̂`(その層の方向)を使う場合:

```
A = Σ_h s_h · (r̂ᵀ W_O の、ヘッド h の列ブロックだけを残したもの)   # (1, n_in)
B = −r̂                                                              # (n_embd, 1)
```

層が 2〜3 個なら LoRA は数百 KB に収まる。llama.cpp の `--lora` でそのまま当てられ、倍率をリクエスト単位で変えられる。

**焼き込み**もできる。**書き換える 1〜数テンソルだけを Q8_0 か F16 にして、他は元のバイトのまま写す**(gne ablate の焼き込みと同じ書き方)。ファイルは数十 MB 増える程度。焼き込み版は、LoRA 版と出力が一致することを確かめる。

なお、この操作は単純な倍率ではないので、量子化ブロックのスケールだけを書き換える方式(スケールパッチ)では表せない。そのため、書き換えるテンソルは量子化し直す必要がある。

### 先行研究との関係

1 つのヘッドについて、この編集は Steer2Edit(Sun et al., [arXiv:2602.09870](https://arxiv.org/abs/2602.09870))と同じ形になる。向こうの `ΔW = λ u kᵀ`(`u = v/|v|`、`k = Wᵀv/|Wᵀv|`)は、`W = W_O[:, blk_h]`、`v = r̂`、`λ = −s_h|Wᵀr̂|` と置くと上の `−s_h r̂ r̂ᵀ W` になる。これを作ったあとに知った。

違いは編集の式ではなく手順にある。

| | Steer2Edit | CHiPS |
|---|---|---|
| 選ぶもの | attention ヘッドと MLP のニューロン | ヘッド(線形 attention の層も含む) |
| 選び方 | steering vector との cos と Elastic-Net | 止めて測る因果の効果と効率 |
| 強さ | 閉じた式と検証用のグリッド | 効率で配り、実際の振る舞いで調整する |

同じ課題で比べたことはないので、優劣は分からない。

## 3. 手順

### 3.0 対照集合を作る

A 側(狙った振る舞いが出ている状態)と B 側(中立)のプロンプト、または同じプロンプトに対する 2 通りの状態。例ごとの作り方は §4。

- **A と B の文体・長さ・話題をできるだけ揃える**。揃っていないと、方向に「長さ」や「話題」が混ざる。
- 各 32〜128 件。多いほど方向は安定するが、方向自体は数十件でも実用になる。

### 3.1 測定用と確認用に分ける

偶数番目を**測定用**(方向を測る、因果を測る、強さを決める)、奇数番目を**確認用**(最終評価にのみ使う)。調整に使った集合で評価すると過剰適合する。

### 3.2 方向を測る

A 側と B 側を、**返事を生成させずにプロンプトの最後まで読ませるだけ**で、層ごとに残差の平均差を取る。

```
r_L = normalize( mean_A(l_out-L) − mean_B(l_out-L) )
```

- **測る位置**は 2 通り試す。`last`(生成プロンプトの最終トークン、または直後のテンプレート数トークン)は「指示を読んだ直後の状態」、`response`(その振る舞いで話している最中の返事トークン)は「その状態で話している最中」。性格や口調では `response` が効く例があり、指示を読んだ時点で決まる性質では `last` が効きやすい。
- **基準の層を選ぶ**: 層ごとに、A と B の射影値の分離度(Cohen の d)を計算し、最大の層を基準にする。中間〜後半の層に出ることが多い。
- **後段の層の方向も保存する**。方向は層を進むにつれて少しずつ回る(基準層の方向とのコサインが後段で 0.4〜0.7 程度まで落ちることがある)。評価の点数は基準層だけでなく、後段の 1〜2 層でも並べて見る。
- ヘッドに当てる方向は、**そのヘッドがある層の方向**を使う(基準層の方向を全ヘッドに使う変種より、層ごとの方向に分けた方が良い例がある)。

### 3.3 速い物差し(生成しない)

調整のループを回すための軽い指標。

```
点数 = mean over 例 ( 測定位置での残差 · r̂_L )
```

A 側と B 側のそれぞれで点数を出す。生成しないので 1 条件が数秒〜十数秒で回る。**強さの探索はすべてこの物差しで行い、生成を伴う評価は候補が固まってからにする**。

### 3.4 因果で効くヘッドを絞る

「方向に沿って書いている量」(直接の寄与)と「止めたときに結果が変わる量」(因果の効き目)は**一致しない**。

- **間接の経路**: ヘッドの出力は後段のヘッドや MLP の入力にもなる。止めると、後段でその方向に書くはずだったユニットも書かなくなり、変化は直接の寄与より大きくなる。
- **補い合い**: 止めても別のユニットが代わりに書き、点数がほとんど変わらないことがある。
- **基準層より後ろのヘッド**は、基準層の方向への直接の寄与にはまったく現れないが、後段の点数を大きく動かすことがある。直接の寄与だけを見ていると見落とす。

測り方:

1. まず**層単位**で、その層のヘッドを全部止めて点数の下がる層を見つける(層数ぶんの試行で済む)。
2. その層のヘッドを**1 個ずつ**止め、後段の点数の下がり方 `d_h` を測る。候補を絞るなら、基準層より前は直接の寄与の上位 100〜200 個、後ろは下がり方の大きい層のヘッド全部。
3. 物差しは**後段の層の点数**にそろえる(基準層だけで見ると、後段で効くヘッドを取りこぼす)。

生成しないので 1 ヘッドあたり数秒。数百ヘッドを現実的な時間で測れる。

**止めた効き目と方向成分の効き目は別物。** Qwen3.5-4B の迎合の方向で全 880 ヘッドの方向成分を反転(s=2)して点数を測ると、止めたときの下がり方との順位相関は 128 本で +0.08 だった(η とは 36 本で +0.92)。止めて上位 4 層に絞る手順は、反転の効きが大きい上位 10 本のうち 1 本しか拾わなかった。止めると壊れるとして外した層や、測らなかった層にも、反転なら動くヘッドがある。

ただし、反転の点数で選んだ組が振る舞いでも良いとは限らない。同じ押し具合にそろえて dev の 150 問で生成すると、乗り換えと正答率はばらばらで、今の組をはっきり超える組はなかった。層全体を反転して絞る場合は、同じ層の正と負のヘッドが打ち消し合って、強いヘッドを落とすことがある(L23 H12 はヘッド単独で -0.94、層全体で -0.80)。

### 3.5 最初の組を作る

効き目の上位 5〜6 個を選び、`s_h = α · d_h / d_max` とする。全体の大きさ `α` は、**A 側の点数が目標値になるように二分探索**で決める。目標は「B 側の点数と同じ高さ」あたりが出発点。

### 3.6 効率で強さを配り直す

丸ごと止めたときの効き目と、**方向成分を強めたときの効き目は別物**。順位が入れ替わることがあるので、介入後の状態で測り直す。

1. 最初の組を当てた状態で、測定用の A 側のうち**点数が高く残っている例**(効きにくい例)を 16 件ほど選ぶ。
2. 候補ヘッドごとに `s_h` を小さく(例えば +3)上げ、その 16 件での点数の下がり方を測る。`s` 1 あたりの下がり方を**効率 η_h** とする。候補は、今の組 + 効き目上位 30 個程度。
3. 同時に、**B 側への影響**もヘッドごとに測る。効率が高くても B 側を動かすヘッドは避ける。
4. 効率に比例させて `s_h ∝ η_h` と**0 から配り直す**。全体の大きさは、効きにくい 16 件の点数が目標に届くまで二分探索。
**比を固定しない配り方(`--method greedy`)。** `s ∝ η` は比を最初の 1 回で固定するので、一番効率の高いヘッドが上限に当たると全部が止まる。s と点数は直線ではなく、η はそのときの状態の傾きでしかない(符号が変わることもある)。greedy は毎回いちばん点数が下がるヘッドだけを `delta_s` 上げて、目標に届くか、B 側の直交成分のずれが `drift_max`(既定 0.5)を超える手前で止まる。s の上限は既定で無い。小さな s では効かず途中から急に効くヘッドがあると、先に上げ始めたヘッドに偏ることがある。

5. **ヘッド数を減らす**: 6 個、5 個、4 個と作り、(a) 点数が残る例の数、(b) B 側の直交成分のずれ がほぼ同じなら、**一番少ない組を採る**。効率の高いヘッドに寄せると、ヘッド数も、最大の `s` も小さくできることが多い。

### 3.7 書き出す

選んだヘッドと強さ(`L:Hh:s` の列)から LoRA を作る。LoRA なしで使いたい場合は焼き込む(§2)。焼き込み版は、LoRA 版と出力が一致することを確認する。

### 3.8 評価する

確認用の集合で、**目的の指標**と**副作用**を並べる。

目的の指標(例ごとに §4):

- 自動判定(判定語、正規表現、形式検査)または judge モデルによる採点
- 1 件の重みを意識する。40 件なら 1 件 = 2.5% で、数 % の差は見分けられない。最終候補は 100 件以上で確かめる

副作用:

| 項目 | 測り方 |
|---|---|
| **直交成分のずれ** | B 側の入力で、介入前後の残差の差のうち `r̂` 以外の成分 ÷ 残差の大きさ。方向成分のずれと並べて出す。これが小さいことが本手法の主張の中心 |
| ループ・繰り返し | 出力末尾の n-gram 重複率、distinct-4。A 側 B 側の両方 |
| 空の出力 | 本文が空になる率。上限を広げて再実行し、「長いだけ」と「本当のループ」を分ける |
| 能力 | 答えの決まった問題の正答率、形式指示の遵守率 |
| ppl | 参照テキスト(英語・日本語・コード)の teacher-forced perplexity |
| 長いタスク | 複数ステップの作業での上限到達率、末尾の多様さ、トークン数 |
| 道具呼び出し | 名前と引数の正しさ、呼ぶべきでないときに呼ばないか、続きのやりとり |
| **ランダム対照** | 同数のヘッドをランダムに選び、同じ強さの分布で当てる。「ヘッドの選び方が効いている」ことを示すための対照。これがないと「どの数個でも同じ」と言われる |
| **全層射影との比較** | 同じ目的指標の水準まで動かしたとき、上の副作用がどれだけ違うか(§6) |

ランダム対照と全層射影との比較は、外に主張する前に必ず回す(gne では `gne eval --random-controls N` と `gne eval --compare-methods`)。

## 4. 例ごとの当てはめ

以下は、手順を振る舞いごとに当てはめた場合の案で、それぞれの例ではまだ確かめていない。

### 4.1 ペルソナ(キャラの性格)

| | |
|---|---|
| A 側 | system でペルソナを与えた状態の返事 |
| B 側 | 中立のアシスタントとしての返事 |
| 測る位置 | `response`(その性格で話している最中の状態) |
| 目的指標 | 性格に特有の語の出現率、judge による 1〜5 の採点 |
| 反応性 | トリガーのある入力とない入力の対を作り、スコアの差を見る。「常に発動」ではなく「状況に反応する」形になっているか |

注意: 性格だけを足すと、一人称や話し手の性別が揺れることがある。その場合は別の方向(話し手の性別、丁寧さ)を少量だけ足して安定させる。方向同士がほぼ直交していることを cos で確かめる。

### 4.2 口調(敬語とタメ口、硬い文と柔らかい文)

| | |
|---|---|
| A 側 / B 側 | **同じ内容**を 2 通りの口調で書いた返事 |
| 測る位置 | `response` |
| 目的指標 | 語尾の分布、丁寧表現の出現率 |

注意: 内容を揃えるのが重要。揃っていないと話題が方向に混ざる。`s` を上げすぎると語尾だけが崩れるので、文法の破綻(distinct-4、ppl)を併せて見る。

### 4.3 言語混入(意図しない言語が混ざるのを抑える)

| | |
|---|---|
| A 側 | 混ざった状態の出力(または混ざる言語のテキスト) |
| B 側 | 目的の言語だけの出力 |
| 測る位置 | `response` |
| 目的指標 | 出力中の、その言語に固有の文字の割合 |
| 使い方 | **抑制が目的なので `s > 1`** で反転側に押す |

注意: その言語を正当に使う場面(その言語で質問された、翻訳を頼まれた)を壊さないか必ず確認する。**B 側とは別に「その言語で質問された場合」の集合を用意して、能力が落ちていないかを見る**。

### 4.4 冗長さ

| | |
|---|---|
| A 側 | 長く冗長な返事(前置き、繰り返し、過剰な箇条書き) |
| B 側 | 同じ内容の簡潔な返事 |
| 測る位置 | `response` |
| 目的指標 | トークン数の中央値、前置き表現の出現率 |

注意: 短くしすぎると情報が落ちる。答えの決まった問題の正答率と、形式指示の遵守率で「短いが正しい」ことを確かめる。長いタスクの評価も必須。

### 4.5 迎合(ユーザーに合わせて事実を曲げる)

| | |
|---|---|
| A 側 | ユーザーの誤った主張に同調した返事 |
| B 側 | 同じ主張に対して事実を優先した返事 |
| 測る位置 | `response`(同調しているか否かは返事の最中に出る) |
| 目的指標 | 誤った主張への同意率、訂正の有無 |

注意: 反転させすぎると、頑固、攻撃的、あるいは正しい指摘まで否定するようになる。**丁寧さと、ユーザーが正しい場合の同意率**を併せて測り、両方が保たれる範囲で止める。

## 5. なぜ丸ごと倍率より副作用が小さいか

効いているヘッドでも、出力のうち狙った方向に沿っているのは一部にすぎない(方向との cos が 0.1〜0.3 程度)。残りは狙いと無関係な情報。

あるヘッドの出力が、方向成分 3、直交成分 10 だったとする。

| やり方 | 方向成分 | 直交成分 | 直交成分の変化 |
|---|---|---|---|
| 元のまま | 3 | 10 | – |
| 丸ごと倍率(k = −5) | −15 | −50 | 60 |
| 方向成分だけ(s = 6) | −15 | 10 | 0 |

**方向成分は同じだけ動かせるのに、直交成分の変化はゼロにできる**。丸ごと倍率で文章の崩れやループが出るのは、変化の大部分が直交成分に行くため。実測でも、中立側の入力での直交成分のずれは、丸ごと倍率より方向成分だけの方が一桁近く小さくなる(Qwen3-0.6B の evil の方向で、同じ点数の水準にそろえたとき 1.63 → 0.15、約 11 分の 1。s が大きく、物差しの層がヘッドのすぐ後ろの組では 1.75 → 0.91 と 2 分の 1 にとどまった。verification.md §20)。

副作用が「狙いとの綱引き」ではなく「関係ない情報の破壊」に由来している場合、変え方を絞るだけで、**同じヘッド・同じ効果水準のまま副作用が消える**。

## 6. 全層射影(abliteration 的な方式)との関係

操作の種類は同じ。どちらも「書き込みから方向成分を取り除く」。違いは当て方。

| | 全層射影 | 本手法 |
|---|---|---|
| 当てる先 | 全層の全書き込み(全ヘッド + 全 MLP) | 因果で選んだ数個のヘッドだけ |
| 強さ | 一律 `s = 1`(消すだけ) | ヘッドごとに違う `s`。`s > 1` で反転も |
| 選び方 | 選ばない | 止めたときの点数の下がり方で選び、介入後の効率で配り直す |
| 成果物 | 全層ぶんの書き換え | 層 1〜3 個、階数 1 の LoRA(数百 KB) |

主張するなら、**同じ目的指標の水準まで動かしたときの副作用の差**で比べる。全層射影の方が確実に効くが、関係ない層まで触るので副作用が出やすい、という形になるはず(ならなければそう記録する)。

## 7. 落とし穴

- **`s > 1` は反転なので、B 側でそのヘッドが逆向きに書いている場合、その分も反転して狙いと逆に押す**。強さを上げるたびに B 側を測り直す。
- **自動判定は取りこぼす**。判定語の一覧で数えると、言い回しを変えた該当例を見落とす。可能なら judge を併用する。
- **少数例では 1 件の差が大きく見える**。候補を絞る段階は少数で回し、最終候補だけ件数を増やす。
- **点数の目標は振る舞いの目標ではない**。同じ「B 側の平均」でも、振る舞いによって近すぎたり遠すぎたりする。迎合では greedy が L20 H18 の s=15 で目標に届いたが、振る舞いには弱すぎて、使えたのは s=38 だった。止める強さは未使用の問題で生成して確かめる。
- **s の上限を外すだけでは解決しない**。`s ∝ η` のまま目標が遠いと、届かせようとして壊れる強さまで上がる。上限(既定 30)に当たった組は、表の `stop` と `capped` で分かる。止まった値に意味はない。
- **s の大きさはヘッドで意味が違う**。同じ s=30 で、壊れないヘッドもモデルを全壊させるヘッド(L0)もある。残差のずれも共通の安全線にはならない(0.31 で正答率が変わらない組も 6 点下がる組もある)。全壊の検出くらいに使う。
- **読んだ返事に合わせて作った正規表現を、読んでいない返事に使わない**。見逃しが増える。件数が大事なら読む判定を入れる。
- **評価の問題が易しいと強さの差が見えない**。天井に近い問題で探すと、残りにくい例を消す調整が見えない。振る舞いが確実に出る、効きにくい問題で評価する。
- **目的指標を限界まで詰めない**。数 % はサンプリングの揺れ。強さを上げても下がらなくなったら、そこで止めて「残る例を担っている別のヘッドを探す」方に切り替える。
- **内部の点数だけで主張しない**。方向の射影値は「方向で押したものを方向で測っている」ので、トートロジーに見える。必ず**外から見える指標**(出力に対する判定)を主指標にする。
- **未検証の使い方を明記する**。多ターン会話、system プロンプトあり、言い換えた入力は、挙動が変わる可能性がある。
- 比較対象が別のファイル(別の量子化)なら、その差も混ざる。

## 8. 時間の目安

生成を伴わない工程が大半なので、調整のループは速い。27B クラス・GPU 1 枚での目安:

| 工程 | 時間 |
|---|---|
| 方向を測る(数十件の prefill) | 10 分程度 |
| 因果スクリーニング(層単位 + 数百ヘッド、1 ヘッド数秒) | 20〜30 分 |
| 組を作る・強さを配り直す(生成なし) | 1 組 2〜3 分 |
| LoRA 書き出し / 焼き込み | 数秒 / 数分 |
| 確認用の全件評価(生成あり) | 1 組 30〜40 分 |
| 長いタスク・道具呼び出し | 30 分程度 |
| perplexity | 数分 |

**候補を絞るまでは生成しない**のが要点。生成を伴う評価は、確定候補の数だけに使う。

## 9. gne での手順

| 手順 | コマンド(MCP のツール) | 生成 |
|---|---|---|
| 3.2 方向を測る | `gne direction --contrast <対照集合>`(`direction`) | なし(`--positions response` は返事を作る) |
| 3.2 基準層・後段の層とのコサイン、3.3 速い物差し | `gne direction score --name <方向>`(`direction_score`) | なし |
| 3.4 因果で絞る | `gne heads causal --name <方向>`(層単位 → ヘッド単位、`heads_causal`) | なし |
| どこを探すかを決める(方向の差を attention・専門家・共有の専門家に分ける) | `gne heads writers --name <方向>`(`--expert-layers` で専門家ごとにも) | なし |
| 3.5〜3.6 組を作り、効率で配り直す・ヘッド数を減らす | `gne heads allocate --name <方向> --target <点数>`(`heads_allocate`)。比を固定しないなら `--method greedy` | なし |
| 3.2〜3.6 をまとめて回す | `gne heads pipeline --spec <JSON>`(`heads_pipeline`、UI の direction ビューで JSON を読み込んでも回せる。用途別のひな形は `configs/pipeline/`) | なし |
| 組で消し切れない質問から、足すヘッドを探す | `gne heads refine --name <配分> --n-heads N`(`heads_refine`、UI の比較表の「残りから追加」)。残りの質問を A、元の B を B にし、両側に組を当てたまま方向を作り直して一括に流し、元の組と合わせたレシピを作って測り直す | なし |
| 全体の倍率を返事で決める | `gne heads candidates --alloc <配分>`(組 × 倍率で返事を作り、どの候補か伏せた採点のファイルを書く)→ 採点 → `gne heads candidates --tally <名前>`(`heads_candidates`・`heads_candidates_tally`、UI のパイプラインのタブからも) | あり |
| 3.7 書き出す | `gne headproj export --recipe <レシピ>`(`--bake` で焼き込み、`--verify` で LoRA 版との一致) | なし |
| 3.8 評価する(ランダム対照・全層射影との比較) | `gne eval --recipe <レシピ> --random-controls 16`、`gne eval --recipe <レシピ> --compare-methods`、`gne eval --alloc <方向> --n-heads 6,5,4,3`(`eval`) | あり |

対照集合の両側は、system の代わりにレシピを当てて作ることもできる(`recipe_a` / `recipe_b`)。側ごとに別の質問を読ませることもでき(`prompts_a` / `prompts_b`)、§3.0 の「A 側と B 側のプロンプト」はこの形で書く。ニューロンのレシピが作った振る舞いについて、方向とそれを運ぶヘッドを探すときに使う。

ユニットは `L:Hh:sS@NAME`(例 `33:H16:s6@evil`)、レシピでは `{layer, kind: head, head, mode: proj, direction, s}`。方向を省くとレシピの `default_direction`、`direction_layer: base` で全ヘッドに基準層の方向を使う。判断の仕方は [agent_playbook.md](agent_playbook.md) §4.4。
