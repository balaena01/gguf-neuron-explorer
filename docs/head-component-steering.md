# CHiPS(Causal Head-isolated Projection Steering)— 方向成分だけを変えるヘッド介入

この手法を CHiPS と呼ぶ。名前の各語の意味は次のとおり。Causal = ヘッドの出力を止めて(0 にして)測り、結果を変えるヘッドを選ぶ。Head-isolated = 選んだヘッドの書き込みだけに限定する。Projection = 方向に沿った成分だけを動かす。Steering = それで振る舞いを変える。一番の特徴は、選んだヘッドだけに限定して射影すること(小文字の i の isolated)。

任意の「振る舞いの方向」について、**止めると結果が変わるヘッドを少数選び、そのヘッドが書くベクトルのうち方向成分だけを変える**手法。ペルソナ、口調、言語混入、冗長さ、迎合などに使える。

- 位置づけ: 全層の全書き込みに一律の射影を当てる方式(§6)と、ヘッドの出力を丸ごと倍率で変える方式(§5)の中間。**どこに当てるかは止めたときの効き目を測って決め、どう変えるかは方向成分に絞る**。
- 前提: 対象モデルで `gne direction` 相当の方向が作れること、ヘッド単位で出力を記録し、介入できること(gne では §9 のコマンド)。
- MLP のニューロンにも同じ射影を当てられる(§2 の後半)。ヘッドとニューロンを同じ物差しで並べて組を作る選び方は §3.9(`--rank writes`)。
- **`gne heads pipeline` の既定は v0.8.0 から §3.9 の `--rank writes`(部品はヘッドだけ)**。§3.4〜3.6 は v0.7.0 までの既定の選び方(`--rank causal`)の手順で、この文書の §3.9 より前と §7 の数は、断りが無ければ `--rank causal` での値。

## 1. 考え方

attention ヘッドは毎トークン、残差と同じ次元のベクトルを残差に足している。このベクトルを 2 つに分ける。

- **方向成分**: 狙った振る舞いの向き `r̂` に沿った部分。「その振る舞いの側にどれだけ押しているか」
- **直交成分**: それ以外。話題、文法、次に来る語など、狙いと関係のない情報

直交成分には一切触らず、方向成分だけを強さ `s` で変える。

```
新しい書き込み = 元の書き込み − s × (元の書き込みのうち r̂ に沿った成分)
```

| s | 効果 |
|---|---|
| 0 | 変化なし |
| 1 | そのヘッドは `r̂` 方向に何も書かなくなる |
| 2 | 方向成分がちょうど反転する |
| > 2 | 反転した成分がさらに大きくなる |

`s` は**ヘッドごとに違う値**を割り当てる(§3.6)。

**入力によって効き方が自然に変わる**のが要点。変化量は「そのヘッドがその入力で `r̂` 方向にどれだけ書いているか」に比例する。狙った状況では大きく変わり、それ以外ではほとんど変わらない。重みの変更は 1 つしかないのに、「その振る舞いを書いているときだけ効く」動きになる。

## 2. 式と重みへの書き方

ヘッドの出力を残差に書き込む重み行列(普通の attention なら `W_O` = `attn_output`、線形注意なら `ssm_out`)のうち、ヘッド `h` の列ブロック `blk_h` だけを書き換える。

```
W_O[:, blk_h]  →  W_O[:, blk_h] − s_h · r̂ r̂ᵀ W_O[:, blk_h]
```

`r̂ r̂ᵀ W_O[:, blk_h]` は「そのヘッドが書くベクトルのうち `r̂` に沿った部分を取り出す」計算。

**LoRA にすると層ごとに階数 1**。同じ層のヘッドが同じ `r̂`(その層の方向)を使う場合:

```
A = Σ_h s_h · (r̂ᵀ W_O の、ヘッド h の列ブロックだけを残したもの)   # (1, n_in)
B = −r̂                                                              # (n_embd, 1)
```

層が 2〜3 個なら LoRA は数百 KB に収まる。llama.cpp の `--lora` でそのまま当てられ、倍率をリクエスト単位で変えられる。

**マージ**もできる。**書き換える 1〜数テンソルだけを Q8_0 か F16 にして、他は元のバイトのまま写す**(gne ablate のマージと同じ書き方)。ファイルは数十 MB 増える程度。マージ版は、LoRA 版と出力が一致することを確かめる。

なお、この操作は単純な倍率ではないので、量子化ブロックのスケールだけを書き換える方式(スケールパッチ)では表せない。そのため、書き換えるテンソルは量子化し直す必要がある。

**MLP のニューロンにも同じ形で当てられる**(ユニット `L:Nn:sS@NAME`、レシピ `{layer, neuron, mode: proj, direction, s}`)。ニューロン `n` が残差に書くベクトルは、活性 `a_n` と、MLP の出力側の重み(`ffn_down`)の `n` 列目 `w_n` の積 `a_n · w_n`。その列から方向成分を引く。

```
w_n  →  w_n − s_n · (r̂ · w_n) · r̂
```

1. `r̂ · w_n` は、ニューロン `n` が活性 1 あたりに `r̂` 方向へ書く量。
2. `s_n = 1` なら、書き換えた列 `w_n − (r̂ · w_n) r̂` と `r̂` の内積は 0 になり、そのニューロンは `r̂` 方向に何も書かなくなる。直交成分はそのまま。
3. 同じ層・同じ方向のニューロンは、ヘッドと同じく `ffn_down` への階数 1 の LoRA に畳める(`A = Σ_n s_n·(r̂ᵀ W_down の n 列目だけ残したもの)`、`B = −r̂`)。

式どおりかは `gne headproj check --layer L --neuron N --direction NAME` で確かめる(MLP の出力の差が `−s · r̂ · (r̂ · w_n) · a_n` と合い、直交成分と同じ層の活性が変わらないこと)。MoE の層と、MLP の出力の後に正規化がある層(post-FFN norm)は対象外。FiSH の「成分を読み取って取り除く形」(場面で開く鍵つきのニューロン、docs/fish.md)とは別物で、こちらはどの入力でも効く。

線形注意(Qwen3.5 系)の出力側 `ssm_out` は、もともとヘッド(V のヘッドごとの列ブロック)として同じ式で扱っている。

**層の書き込み全体にも当てられる**(v0.8.1。ユニット `L:attn:sS@NAME` と `L:ffn:sS@NAME`、レシピ `{layer, kind: attn, mode: proj, direction, s}`・`{layer, kind: ffn, …}`)。`attn` はその層の注意の出力全体(`attn_output`、線形注意の層では `ssm_out`)、`ffn` はその層の MLP の出力全体(`ffn_down`)で、行列全体から方向成分を引く。

```
W  →  W − s · r̂ (r̂ᵀ W)
```

その層の全部のヘッド(全部のニューロン)を同じ `s` で射影したのと同じで、LoRA は階数 1(`A = s · r̂ᵀW`、`B = −r̂`)。同じ層の同じ行列のヘッド(ニューロン)のユニットと一緒に書くと、同じ LoRA に足し算で入る(列が重なる分は二重に引く)。重みを 2 回使うモデルでは、ヘッドと同じく両方の回に当たる(回ごとに当てる形でも使える)。式どおりかは `gne headproj check --layer L --whole attn --direction NAME`(`--whole ffn` で MLP の出力全体)で確かめる。ランダムな対照は、同じ種類の別の層に替える。

### 先行研究との関係

1 つのヘッドについて、この編集は Steer2Edit(Sun et al., [arXiv:2602.09870](https://arxiv.org/abs/2602.09870))と同じ形になる。向こうの `ΔW = λ u kᵀ`(`u = v/|v|`、`k = Wᵀv/|Wᵀv|`)は、`W = W_O[:, blk_h]`、`v = r̂`、`λ = −s_h|Wᵀr̂|` と置くと上の `−s_h r̂ r̂ᵀ W` になる。これを作ったあとに知った。

違いは編集の式ではなく手順にある。

| | Steer2Edit | CHiPS |
|---|---|---|
| 選ぶもの | attention ヘッドと MLP のニューロン | ヘッド(線形 attention の層も含む)。`--rank writes` ではニューロンも |
| 選び方 | steering vector との cos と Elastic-Net | 止めたときの効果(§3.4)と、強めたときの効率(§3.6)。`--rank writes` では方向への書き込みの量と、s=1 で流し直した効き目(§3.9) |
| 強さ | 閉じた式と検証用のグリッド | 効率で配り、実際の振る舞いで調整する。`--rank writes` では s=1 から始め、足りないときだけ上げる |

同じ課題で比べたことはないので、優劣は分からない。

## 3. 手順

### 3.0 対照集合を作る

A 側(狙った振る舞いが出ている状態)と B 側(中立)のプロンプト、または同じプロンプトに対する 2 通りの状態。例ごとの作り方は §4。

- **A と B の文体・長さ・話題をできるだけ揃える**。揃っていないと、方向に「長さ」や「話題」が混ざる。
- 各 32〜128 件。多いほど方向は安定するが、方向自体は数十件でも実用になる。

### 3.1 測定用と確認用に分ける

偶数番目を**測定用**(方向を測る、止めたときの効き目を測る、強さを決める)、奇数番目を**確認用**(最終評価にのみ使う)。調整に使った集合で評価すると過剰適合する。

### 3.2 方向を測る

A 側と B 側を、**応答を生成させずにプロンプトの最後まで読ませるだけ**で、層ごとに残差の平均差を取る。

```
r_L = normalize( mean_A(l_out-L) − mean_B(l_out-L) )
```

- **測る位置**は 2 通り試す。`last`(生成プロンプトの最終トークン、または直後のテンプレート数トークン)は「指示を読んだ直後の状態」、`response`(その振る舞いで話している最中の応答トークン)は「その状態で話している最中」。性格や口調では `response` が効く例があり、指示を読んだ時点で決まる性質では `last` が効きやすい。
- **基準の層を選ぶ**: 層ごとに、A と B の射影値の分離度(Cohen の d)を計算し、最大の層を基準にする。中間〜後半の層に出ることが多い。
- **後段の層の方向も保存する**。方向は層を進むにつれて少しずつ回る(基準層の方向とのコサインが後段で 0.4〜0.7 程度まで落ちることがある)。評価では、方向への射影の値(その性格の度合いの指標、§3.3)を基準層だけでなく、後段の 1〜2 層でも並べて見る。
- ヘッドに当てる方向は、**そのヘッドがある層の方向**を使う(基準層の方向を全ヘッドに使う変種より、層ごとの方向に分けた方が良い例がある)。

### 3.3 速い指標(生成しない)

調整のループを回すための軽い指標として、方向への射影の値を使う。例ごとに、測定位置の残差を方向 `r̂_L` に射影し、その平均を取る。その振る舞いの度合いの指標になる(UI と出力でも「射影の値」と書く。結果の項目名は `score_a`・`score_layer` など、`score` のつく名前)。

```
射影の値 = mean over 例 ( 測定位置での残差 · r̂_L )
```

A 側と B 側のそれぞれで射影の値を出す。生成しないので 1 条件が数秒〜十数秒で回る。**強さの探索はすべてこの指標で行い、生成を伴う評価は候補が固まってからにする**。

### 3.4 止めたときの効き目でヘッドを絞る

(§3.4〜3.6 は `--rank causal`、v0.7.0 までの既定の選び方。v0.8.0 からの既定は §3.9。)

ヘッドが方向に沿って書いている量(直接の寄与)と、そのヘッドの出力を 0 にしたとき(以下「止める」)に結果が変わる量(効き目)は、**一致しない**。

- **後段を通じた効果**: ヘッドの出力は後段のヘッドや MLP の入力にもなる。止めると、後段でその方向に書くはずだったユニットも書かなくなり、変化は直接の寄与より大きくなる。
- **ほかのユニットによる補い**: 止めても別のユニットが代わりに書き、射影の値がほとんど変わらないことがある。
- **基準層より後ろのヘッド**は、基準層の方向への直接の寄与にはまったく現れないが、後段の層の射影の値を大きく動かすことがある。直接の寄与だけを見ていると見落とす。

測り方:

1. まず**層単位**で、その層のヘッドを全部止めて、射影の値が下がる層を見つける(層数ぶんの試行で済む)。
2. その層のヘッドを**1 個ずつ**止め、後段の層での射影の値の下がり方 `d_h`(効き目)を測る。候補を絞るなら、基準層より前は直接の寄与の上位 100〜200 個、後ろは下がり方の大きい層のヘッド全部。
3. 射影の値は**後段の層**で測る(基準層だけで見ると、後段で効くヘッドを取りこぼす)。

生成しないので 1 ヘッドあたり数秒。数百ヘッドを現実的な時間で測れる。

**止めたときの効き目と、方向成分を変えたときの効き目は別物。** Qwen3.5-4B の迎合の方向で、全 880 ヘッドの方向成分をヘッドごとに反転(s=2)して射影の値を測った。止めたときの下がり方との順位相関は、128 本で +0.08 だった(§3.6 の効率 η とは 36 本で +0.92)。層ごとに止めて上位 4 層に絞る手順は、反転の効きが大きい上位 10 本のうち 1 本しか拾わなかった。止めると壊れるとして外した層や、測らなかった層にも、反転なら動くヘッドがある。

ただし、反転したときの射影の値で選んだ組が、振る舞いでも良いとは限らない。射影の値が同じだけ動くように強さをそろえ、調整用(dev)の 150 問で生成すると、乗り換え(素では正しく答える問題で、ユーザーが示した誤った答えに変えること)と正答率は組によってばらばらで、今の組をはっきり超える組はなかった。層全体を反転して絞る場合は、同じ層の正と負のヘッドが打ち消し合って、強いヘッドを落とすことがある(射影の値の下がり方は、L23 H12 単独の反転で -0.94、L23 全体の反転で -0.80)。

### 3.5 最初の組を作る

効き目の上位 5〜6 個を選び、`s_h = α · d_h / d_max` とする。全体の大きさ `α` は、**A 側の射影の値が目標値になるように二分探索**で決める。目標は「B 側の射影の値と同じ高さ」あたりが出発点。

### 3.6 効率で強さを配り直す

丸ごと止めたときの効き目と、**方向成分を強めたときの効き目は別物**。順位が入れ替わることがあるので、介入後の状態で測り直す。

1. 最初の組を当てた状態で、測定用の A 側のうち**射影の値が高いまま残っている例**(効きにくい例)を 16 件ほど選ぶ。
2. 候補ヘッドごとに `s_h` を小さく(例えば +3)上げ、その 16 件での射影の値の下がり方を測る。`s` 1 あたりの下がり方を**効率 η_h** とする。候補は、今の組 + 効き目上位 30 個程度。
3. 同時に、**B 側への影響**もヘッドごとに測る。効率が高くても B 側を動かすヘッドは避ける。
4. 効率に比例させて `s_h ∝ η_h` と**0 から配り直す**。全体の大きさは、効きにくい 16 件の射影の値が目標に届くまで二分探索。
5. **ヘッド数を減らす**: 6 個、5 個、4 個と作り、(a) 射影の値が目標まで下がらずに残る例の数、(b) B 側の直交成分のずれ(§3.8)がほぼ同じなら、**一番少ない組を採る**。効率の高いヘッドに寄せると、ヘッド数も、最大の `s` も小さくできることが多い。

**MoE で、残差が 4 本の流れ(hyper-connections)のモデル(Qwen3.8-Flash-Next)で分かったこと。** 少数のヘッドだけでは、振る舞いは一部しか変わらなかった。

- **少数ヘッド + attention の abliteration:** 少数ヘッドの組に、全ヘッドの射影(`gne headproj ablate`、attention の出力だけから方向を消す)を重ねると、大きく変わった。全ヘッドの射影だけでは、ほとんど変わらなかった。少数ヘッドで要のところを崩し、全体に薄く残った分を全ヘッドの射影で削る、という分担になる。方向の違う組は `gne recipe-combine` で 1 つのレシピにまとめられる。
- **長さをそろえて測る:** 少数ヘッドの組だけだと、応答を長く書かせたときに、途中で元の振る舞いに戻るものが増えた。短い `max_tokens` で測ると効いて見えるので、最後は十分な長さで測る。
- **途中まで書いた応答で対照集合を作らない:** 同じ質問への 2 種類の応答を途中まで書いたものを A・B にすると、差のほとんどが文章の中身の違いになり、同じ質問の中でも向きがそろわなかった(cos 0.1 前後)。見つかるヘッドの効き目も小さかった。
- **効率で配り直す組は前の層に偏ることがある:** L1・L2 のヘッドばかりが選ばれることがあった。効き目に比例した最初の組(`<名前>.alloc-initial.yaml`)とも比べ、候補の層は `heads allocate --candidate-layers` で絞れる。

**射影の値を測る層のヘッドは候補にしない。** 射影の値を測る層とそれより後の層のヘッドは、測る量を直接動かせるので効率が高く見え、配分がそこに偏る。Qwen3.8-Flash-Next では、測る層(L46)のヘッドだけの組は、射影の値で目標に届いても、振る舞いはランダムなヘッドと同じく変わらなかった。L36・L44 のヘッドの組では大きく変わった。`heads causal`(`--layers auto`)・`heads allocate`・`heads pipeline --rank causal` は、既定でこれらのヘッドを外す。`--include-score-layers` で戻せる。`--rank writes`(§3.9)は、選ぶ層(既定は最後に測れる層)とそれより後ろの部品を候補にしない。

**比を固定しない配り方(`--method greedy`)。** `s ∝ η` は比を最初の 1 回で固定するので、一番効率の高いヘッドが s の上限に当たると、配分全体がそれ以上進まない。s と射影の値の関係は直線ではなく、η はそのときの状態での傾きでしかない(符号が変わることもある)。greedy は毎回、いちばん射影の値が下がるヘッドだけを `delta_s` 上げる。目標に届くか、B 側の直交成分のずれが `drift_max`(既定 0.5)を超える手前で止まる。s の上限は既定で無い。小さな s では効かず途中から急に効くヘッドがあると、先に上げ始めたヘッドに偏ることがある。

### 3.7 書き出す

選んだヘッドと強さ(`L:Hh:s` の列)から LoRA を作る。LoRA なしで使いたい場合はマージする(§2)。マージ版は、LoRA 版と出力が一致することを確認する。

### 3.8 評価する

確認用の集合で、**目的の指標**と**副作用**を並べる。

目的の指標(例ごとに §4):

- 自動判定(判定語、正規表現、形式検査)または judge モデルによる採点
- 1 件の重みを意識する。40 件なら 1 件 = 2.5% で、数 % の差は見分けられない。最終候補は 100 件以上で確かめる

副作用:

| 項目 | 測り方 |
|---|---|
| **直交成分のずれ** | B 側の入力で、介入前後の残差の差のうち `r̂` 以外の成分 ÷ 残差の大きさ。方向成分のずれと並べて出す。これが小さいことが本手法の主張の中心 |
| ループ・繰り返し | 出力末尾の n-gram 重複率、distinct-4。A 側 B 側の両方 |
| 空の出力 | 本文が空になる率。上限を広げて再実行し、「長いだけ」と「本当のループ」を分ける |
| 能力 | 答えの決まった問題の正答率、形式指示の遵守率 |
| ppl | 参照テキスト(英語・日本語・コード)の teacher-forced perplexity |
| 長いタスク | 複数ステップの作業での上限到達率、末尾の多様さ、トークン数 |
| 道具呼び出し | 名前と引数の正しさ、呼ぶべきでないときに呼ばないか、続きのやりとり |
| **ランダム対照** | 同数のヘッドをランダムに選び、同じ強さの分布で当てる。「ヘッドの選び方が効いている」ことを示すための対照。これがないと「どの数個でも同じ」と言われる |
| **全層射影との比較** | 同じ目的指標の水準まで動かしたとき、上の副作用がどれだけ違うか(§6) |

ランダム対照と全層射影との比較は、外に主張する前に必ず回す(gne では `gne eval --random-controls N` と `gne eval --compare-methods`)。

### 3.9 全部の部品を、書き込みの量で一度に並べる(`gne heads writes`・`gne heads pipeline --rank writes`)

§3.4〜3.6 の選び方(以下「止めて選ぶ流れ」、`--rank causal`、v0.7.0 までの既定)には、候補が漏れる箇所が 3 つある(§7 の「分かっている限界」)。`--rank writes`(v0.8.0 からの既定)は、候補の作り方と組の作り方を次のように置き換える。部品の種類の既定はヘッド(注意ヘッドと線形注意のヘッド)だけで、ニューロンは `--unit-kinds all` で足す。

**1. 順位づけ(質問 1 問につき 1 回流すだけ)。** 全部の層の、注意ヘッド・線形注意のヘッド・MLP のニューロンについて、方向にどれだけ書いたかを読む。層 `L` の部品が書くベクトルを `v`、その層の方向を `r̂_L` とすると、

```
ヘッド h:      v·r̂_L = x_h · (r̂_Lᵀ W_O[:, blk_h])      (x_h はヘッドの出力、W_O は attn_output か ssm_out)
ニューロン n:  v·r̂_L = a_n · (r̂_L · w_n)              (a_n は活性、w_n は ffn_down の n 列目)
```

s=1 の射影は、この量の分だけ `r̂_L` 方向の書き込みを消す。後ろの層での変換を無視すると、選ぶ層 `S` の射影の値は `(v·r̂_L)(r̂_L·r̂_S)` だけ下がる。そこで点数を

```
点数 = [A 側の全部の質問での平均 − B 側の全部の質問での平均](v·r̂_L) × (r̂_L·r̂_S)
```

とする(「s=1 の射影で、選ぶ層の A と B の差が直接どれだけ縮むか」)。選ぶ層の既定は最後に測れる層(本流の層の数 − 2。MTP の層は GGUF の層の数に入るが本流では実行されないので数えない。v0.8.3 までは MTP つきの GGUF で 1 つ後ろの層を選んで止まった)で、それより前の全部の層の部品が候補になる。質問は間引かない。
- 重みを 2 回使うモデル(sensenova_loop)で書き換えを両方の回に当てるときは、同じ重みの 2 回分を足す。2 本の流れの中の層では、副層の出力 `y` は 2 本に `post₀·y`・`post₁·y` として足され、2 本を混ぜる行列は行も列も和が 1 なので、2 本の平均の残差の増分は `c·y`(`c = (post₀ + post₁)/2`、`post` はルーターの値)。書き込みにはこの `c` を掛ける。
- 確かめ: 層ごとに、部品の和が捕まえた層の出力と合うか、部品から組み立てた層の更新が残差の差 `l_out(L) − l_out(L−1)` と合うかを出す(`check`)。
- 層ごとの直接の書き込み(`layer_scores`、v0.8.1): 層ごとに、注意の出力全体・MLP の出力全体を s=1 で射影したときに選ぶ層で直接に縮む A−B の差の割合を、部品の種類の指定に関係なく出す(CLI・UI の「層ごとの直接の書き込み ÷ 差」)。どの層の書き込み全体が効くかの目安。
- 層の書き込み全体を部品にする(v0.8.1、`--unit-kinds layers`、`heads,layers` や `all,layers` のように足す): その層の注意の出力全体(`L:attn`)・MLP の出力全体(`L:ffn`)を 1 つの部品として、ヘッド・ニューロンと同じ順位表に並べる。点数はその層の全部のヘッド(全部のニューロン)の点数の和。確かめは proj だけ(`--verify-mode ablate` では使えない)。
- 重みを 2 回使うモデルで両方の回に当てるときは、ループの中の部品をどちらの回の段の方向で測り・射影するかを `--loop-direction first`(既定、1 回目の段)/ `second`(2 回目の段。部品の番号も 2 回目の段で表す)で選べる(比べた結果は sensenova_loop.md)。

**2. 上位を 1 個ずつ流し直して確かめる。** 点数の上位 `verify_top` 個(既定 64)と、その下(上位の数の 4 倍まで)から等間隔に `verify_sample` 個(既定 16)を、1 個ずつ s=1 で射影して(`--verify-mode ablate` なら出力を 0 にして)流し直し、§3.4 と同じ物差しで測る(選ぶ層での A 側の下がり方、B 側の射影の値の変化、B 側の直交成分のずれ)。点数と、測った「A−B の差の縮み」の順位相関(Spearman)を、全体と種類ごとに出す。B 側の直交成分のずれが 0.5 を超える部品は外す。

**3. s=1 から組を作る。**
1. 確かめた部品を、「A 側の下がり − B 側の射影の値の動きの大きさ」の大きい順に並べる。A と B の差の縮みで並べないのは、B 側の射影の値が A 側の向きに上がる部品(差は縮むが、ふつうの入力が振る舞いの側に寄る)を上に置かないため。
2. 上から 1 個ずつ s=1 で組に足し、組全体を流し直す。A 側の平均が下がり、組の効き(下の式)が増え、2 つの上限(下)の中のときだけ採る。A 側の平均が目標に届くか、数が上限(`n_units`、既定 24・12・6)に達したら止める。ここで届けば、強さは全部 1。
3. 届かなければ、強さを上げる。既定(v0.8.3 から)は**部品ごと**(`--strength per_unit`、下の「部品ごとの強さ」)。`--strength uniform` は組の全部の s を同じ倍率 α で上げる(v0.8.0〜0.8.2 の決め方で、以下はその説明。安全の基準は部品ごとでも同じ)。s が 1 を超えると射影は成分を反転させる(`w ← w − s(r̂·w)r̂` の `r̂` 成分は `(1 − s)` 倍)。B 側の入力で方向と逆向きに書いていた部品は方向に沿って書くようになり、B 側(ふつうの入力)の射影の値が A 側へ動くことがある。そこで α ごとに次を測る。
   ```
   A 側の下がり = 無介入の A 側の平均 − A 側の平均
   B Δ         = B 側の平均 − 無介入の B 側の平均
   組の効き     = A 側の下がり − |B Δ|        (1 個ずつの確かめで並べる鍵と同じ考え方を、組に当てる)
   上限         = B 側の直交成分のずれ ≤ 0.5、B 側が A 側へ動く量 ≤ 0.10 ×(無介入の A 側の平均 − B 側の平均)
   ```
   α は 1 から `s_max`(既定 30)まで等比の格子(10 点)で上にたどる。
   - 目標に届き、上限の中 → その点と手前の点のあいだを二分探索で詰め、届く最小の α を使う(`stop`: `raised`)。
   - 上限を超えた → 手前の点とのあいだで上限の中の最大の α を探し、そこで止める(`b_move` = B 側が A 側へ動く、`drift` = 直交成分のずれ)。
   - 組の効きが A と B の差の 1% より増えない点が 2 つ続いた → そこで止める(`no_gain` = 上げても良くならない)。
   - 格子の終わり → `s_max`。
   届かずに止めたときは、いちばん大きい α ではなく、測った上限の中の点のうち組の効きがいちばん大きい α を使う(増え方が差の 1% 以下なら低い α を残す。α = 1 も候補)。α ごとの A 平均・B Δ・B ⊥・組の効きは、表の行の `raise` に残る(UI では行の「倍率ごと」、CLI では「倍率ごと:」の行)。`target` は全部 1 で届いた組。
   **部品ごとの強さ(既定、v0.8.3)。** s=1 の組(どの部品も s=1)から、次を最大 6 回くり返す。
   1. 射影の値が残りやすい質問(目標を超えたまま残っている A 側の質問のうち、値の大きい順に `--hard` 個、既定 16)を選び、部品ごとに s を 1.5 倍にしてみて(ほかはそのまま)、その質問での A 側の下がり − B 側の動きの大きさの増え方を、強さ 1 あたりの効率として測る。上限(B 側が A 側へ動く量・直交成分のずれ)を超える部品は上げない。平均は届きそうでも個別に残る質問があるとき、そこに効く部品を先に上げるため、残りやすい質問で測る(回ごとに選び直す)。
   2. 上げ幅を効率に比例して配る(いちばん効く部品の s が 1 + t 倍。効率が 0 以下の部品は据え置き)。
   3. t = 0.5, 1, 2, 4, 8 を全部の質問で試し、一律と同じ規則(目標に届けば届く最小の t、上限を超えたら手前、組の効きが差の 1% より増えない点が 2 つ続いたら止める)で、組の効きがいちばん良い点を採る。効率の向きで組の効きが増えないときだけ、全部を同じ割合で上げる向き(上限を超える試しになった部品は除く)で同じように試す(部品が多いと 1 個ずつの試しでは組がほとんど変わらず、効率の向きだけでは上がらないことがあった)。
   部品は外さず、s は 1 以上・`s_max` 以下。効く部品は高く、B 側を押す部品は低くなり、部品ごとの強さは大きく違ってよい。回ごとに選んだ質問(文と射影の値)と、部品ごとの s・効率(上げられなかった部品はその理由)は表の行の `probes` に残る(UI の行の「強さの決め方」、v0.8.4)。回ごとの強さの最大・中央値・最小と A 平均・B Δ・B ⊥ は表の行の `raise` に残る(UI・CLI の「回ごと」)。止めた理由は `raised` / `no_gain` / `iters`(回数の上限)/ `b_move` / `drift`。
   v0.8.0〜0.8.2 が一律だったのは、v0.7.0 の配り直し(効率に比例して 0 から配る)で効き目の大きいヘッドが外れ、少数のヘッドに s 20〜30 が集まったのを避けるため、配り直しの段ごと外したから。直すべきだったのは部品が外れることと上限の無さで、部品ごとに強さを変えることではなかった。部品を少なくするほど個別の調整が要る(v0.7.0 まではしていた)ので、部品を外さず上限の中で配る形で戻した。公開のひな形での比較で既定を決めたのではなく(題材に偏りがあり、そこでの比較で一律を選んだことが不備の元だった)、部品ごとと一律の差は公開のひな形では確かめていない(動作の確認だけ)。
   B 側が A 側へ動く量の上限 0.10 は、公開のひな形での値から決めた。v0.8.0 の比較(下の表)で目標に届き、応答も良かった `--rank writes` の組は、B Δ ÷(A と B の差)が −0.24〜+0.04(A 側へは最大 +0.04)。B 側にも振る舞いが出た組は、Qwen3.5-4B の disclaimer の (1) が +0.18〜+0.19(B 側の一致 1/26 → 9/29)、SenseNova-Loop-9B の question_kinds の (1) が +0.89〜+0.90(英語の質問に日本語で答えた、28/28)。0.10 はその間にある。A 側から離れる向きには上限を付けない(良い組で −0.24 まであった)が、組の効きでは同じ重さで引く。
4. 表には、上限の数ごとの組のほかに、倍率を上げる前の組(採った部品を全部 s=1、「取り除くだけでどこまで届くか」)の行がいつも 1 行出る(結果の `allocate.s1`、レシピ `<name>.alloc-s1.yaml`)。推す組は次の順で決める。
   - 目標に届いた組があれば、§3.6 と同じ規則。
   - どれも届かなければ、上限の中で組の効きが正の組のうち、効きがいちばん大きい組(差の 5% 以内は同じとみなして、数の少ない組)。結果の `recommended.reached` が `false` になり、「目標に届かない」と出る。
   - どちらも無ければ推さない。結果の `no_recommend` に理由が入り、次の手(`--rank causal`、`--unit-kinds` で部品の種類を変える、`heads refine` で残りの質問から部品を足す)が出る。
   効率で 0 から配り直す段は無いので、効き目の大きい部品が外れることはない。
5. 層全体の部品と、同じ層の同じ行列の個別の部品(注意全体とその層のヘッド、MLP 全体とその層のニューロン)は、両方は組に入れない(同じ列を二重に引くことになる)。層全体を試すときは、組の中の同じ行列の個別の部品と入れ替えて比べ(組の効きが増え、上限の中なら採る)、層全体が組にあれば、その行列の個別の部品は試さない。層全体の部品も、ほかの部品と同じく B 側の動きと直交成分のずれの上限を通す。

**4. 応答での確かめ(`check_replies`、既定 16 問、0 で切る)。** 推す組(無ければ残る数が最少の組)と無介入で、対照集合の両側の質問に応答を書かせ、書き終えた応答のうち `validate.match` に一致した数・空・繰り返し・上限で切れた数を並べる。A 側の一致がほとんど減らないときは知らせ、`--rank causal` も試すよう勧める(結果の `check.note`・`check.suggest`)。無介入でも A 側の一致が書き終えた応答の半分に満たないときは、正規表現が応答に合っていないかモデルが A 側の振る舞いをしていない疑いがあるので、この数は当てにならないと知らせる(`check.match_warning`)。組を当てると繰り返し・空の応答が側の質問の 1/4 以上(2 問以上)増えたときも知らせる(`check.break_warning`、v0.8.1)。一括の出力には、どちらの選び方で流したか(`rank`)も出る。選ぶのに使った質問での確かめなので、最後は調整に使っていない質問で `gne behave` を流す。

**知らせ(`allocate.notes`)。** 倍率を上げる前の組が目標までの差の半分も縮めないとき(直接書き込む部品を取り除くだけでは届かず、強さを上げて成分を反転させて届かせている題材)と、重みを 2 回使うモデルで組にループの中の部品が入ったとき(1 回目にも効く。表には 1 回目の出口の段での A・B の変化と B 側の直交成分のずれも出る)に、1 行ずつ出す。

**UI(「CHiPS」の画面)。** 設定の欄は、候補の探し方ごとに「書き込みの量で全部から選ぶときの設定」(部品・組の大きさの上限 `n_units`、「細かい設定」に確かめる部品の数 `verify_top`・応答での確かめの質問の数 `check_replies` と上限のトークン数 `check_tokens`・選ぶ質問と測る質問を分ける `holdout`・ループの中の部品の方向 `loop_direction`)と「止めて選ぶときの設定」(ヘッド数・ヘッドを測る層の数)に分かれ、選んでいない探し方のまとまりは無効になる(ジョブにも渡さない)。書き込みの量で選ぶときの設定には強さの決め方(部品ごと・全部を同じ倍率)もある。残りやすい質問の数はどちらの探し方でも使うので、共通の欄にある(v0.8.3)。ループの中の部品の方向は、同じ層を 2 回実行するモデルのときだけ選べる。欄の値が使われ、JSON の `pipeline` に同じ項目があれば読み込んだときにその値が欄に入る(v0.8.2)。

**選ぶ質問と表の数を測る質問を分ける(`--holdout`、v0.8.1)。** 確かめ・組づくり・表の「残り」は同じ質問で測るので、効き目の順に部品を選ぶと表の数は楽観的になる。`--holdout` を付けると、質問を偶数番目(方向・順位づけ・確かめ・組づくり)と奇数番目に分け、表の各行(と倍率を上げる前の組)の A 側の平均・残り・B 側の変化・直交成分のずれ・組の効きを奇数番目の質問で測り直し(`allocate.table[].holdout`)、応答での確かめも奇数番目の質問で行う。側ごとに 16 問以上要る。推す組は選ぶ側の数で決める(測り直した数は並べて出す)。既定は切ってある(公開のひな形は各側 16〜20 問で、選ぶのに使える質問が半分になるため)。

**弱点。** 順位づけは直接の書き込みだけを見る。後ろの層の書き手を動かしているだけの部品(その部品の書き込みは方向に沿っていないが、後ろの MLP やヘッドの入力を変えて、方向への書き込みを増やしている部品)は、点数に出ない。2. の確かめと順位相関は、そのずれの大きさを見るためのもの。勾配を使う見積もり(間接の経路も含む)は、今後の課題。

**確かめ(公開のひな形 3 つ・2 つのモデル)。** 同じひな形・同じモデルで、(1) 止めて選ぶ流れ(`--rank causal`、v0.7.0 までの既定)、(2) `--rank writes --unit-kinds heads`(v0.8.0 からの既定)、(3) `--rank writes --unit-kinds all`(ヘッド + ニューロン)を、目標 `B` で比べた。応答は、選ぶのにも方向づくりにも使っていない質問の各側 30 問(greedy、上限 1,024 トークン)。「A 一致」「B 一致」は書き終えた応答のうち `validate.match` に一致した数。評価する組は推す組(無ければ残る数が最少の組)。(1) は推す組が無いと 4 個の組になるので、前の報告と同じ 6 個の組も並べた(1')。

## 4. 例ごとの当てはめ

以下は、手順を振る舞いごとに当てはめた場合の案で、それぞれの例ではまだ確かめていない。

### 4.1 ペルソナ(キャラの性格)

| | |
|---|---|
| A 側 | system でペルソナを与えた状態の応答 |
| B 側 | 中立のアシスタントとしての応答 |
| 測る位置 | `response`(その性格で話している最中の状態) |
| 目的指標 | 性格に特有の語の出現率、judge による 1〜5 の採点 |
| 反応性 | トリガーのある入力とない入力の対を作り、スコアの差を見る。「常に発動」ではなく「状況に反応する」形になっているか |

注意: 性格だけを足すと、一人称や話し手の性別が揺れることがある。その場合は別の方向(話し手の性別、丁寧さ)を少量だけ足して安定させる。方向同士がほぼ直交していることを cos で確かめる。

### 4.2 口調(敬語とタメ口、硬い文と柔らかい文)

| | |
|---|---|
| A 側 / B 側 | **同じ内容**を 2 通りの口調で書いた応答 |
| 測る位置 | `response` |
| 目的指標 | 語尾の分布、丁寧表現の出現率 |

注意: 内容を揃えるのが重要。揃っていないと話題が方向に混ざる。`s` を上げすぎると語尾だけが崩れるので、文法の破綻(distinct-4、ppl)を併せて見る。

### 4.3 言語混入(意図しない言語が混ざるのを抑える)

| | |
|---|---|
| A 側 | 混ざった状態の出力(または混ざる言語のテキスト) |
| B 側 | 目的の言語だけの出力 |
| 測る位置 | `response` |
| 目的指標 | 出力中の、その言語に固有の文字の割合 |
| 使い方 | **抑制が目的なので `s > 1`** で反転側に押す |

注意: その言語を正当に使う場面(その言語で質問された、翻訳を頼まれた)を壊さないか必ず確認する。**B 側とは別に「その言語で質問された場合」の集合を用意して、能力が落ちていないかを見る**。

### 4.4 冗長さ

| | |
|---|---|
| A 側 | 長く冗長な応答(前置き、繰り返し、過剰な箇条書き) |
| B 側 | 同じ内容の簡潔な応答 |
| 測る位置 | `response` |
| 目的指標 | トークン数の中央値、前置き表現の出現率 |

注意: 短くしすぎると情報が落ちる。答えの決まった問題の正答率と、形式指示の遵守率で「短いが正しい」ことを確かめる。長いタスクの評価も必須。

### 4.5 迎合(ユーザーに合わせて事実を曲げる)

| | |
|---|---|
| A 側 | ユーザーの誤った主張に同調した応答 |
| B 側 | 同じ主張に対して事実を優先した応答 |
| 測る位置 | `response`(同調しているか否かは応答の最中に出る) |
| 目的指標 | 誤った主張への同意率、訂正の有無 |

注意: 反転させすぎると、頑固、攻撃的、あるいは正しい指摘まで否定するようになる。**丁寧さと、ユーザーが正しい場合の同意率**を併せて測り、両方が保たれる範囲で止める。

## 5. なぜ丸ごと倍率より副作用が小さいか

効いているヘッドでも、出力のうち狙った方向に沿っているのは一部にすぎない(方向との cos が 0.1〜0.3 程度)。残りは狙いと無関係な情報。

あるヘッドの出力が、方向成分 3、直交成分 10 だったとする。

| やり方 | 方向成分 | 直交成分 | 直交成分の変化 |
|---|---|---|---|
| 元のまま | 3 | 10 | – |
| 丸ごと倍率(k = −5) | −15 | −50 | 60 |
| 方向成分だけ(s = 6) | −15 | 10 | 0 |

**方向成分は同じだけ動かせるのに、直交成分の変化はゼロにできる**。丸ごと倍率で文章の崩れやループが出るのは、変化の大部分が直交成分に行くため。実測でも、中立側(B 側)の入力での直交成分のずれは、丸ごと倍率より方向成分だけの方が一桁近く小さくなる。Qwen3-0.6B の evil の方向で、射影の値を同じ水準にそろえたとき、1.63 → 0.15(約 11 分の 1)。ただし、s が大きく、射影の値を測る層がヘッドのすぐ後ろにある組では、1.75 → 0.91 と 2 分の 1 にとどまった(verification.md §20)。

副作用が「狙いとの綱引き」ではなく「関係ない情報の破壊」に由来している場合、変え方を絞るだけで、**同じヘッド・同じ効果水準のまま副作用が消える**。

## 6. 全層射影(abliteration 的な方式)との関係

操作の種類は同じ。どちらも「書き込みから方向成分を取り除く」。違いは当て方。

| | 全層射影 | 本手法 |
|---|---|---|
| 当てる先 | 全層の全書き込み(全ヘッド + 全 MLP) | 止めたときの効き目で選んだ数個のヘッドだけ |
| 強さ | 一律 `s = 1`(消すだけ) | ヘッドごとに違う `s`。`s > 1` で反転も |
| 選び方 | 選ばない | 止めたときの射影の値の下がり方で選び、介入後の効率で配り直す |
| 成果物 | 全層ぶんの書き換え | 層 1〜3 個、階数 1 の LoRA(数百 KB) |

主張するなら、**同じ目的指標の水準まで動かしたときの副作用の差**で比べる。全層射影の方が確実に効くが、関係ない層まで触るので副作用が出やすい、という形になるはず(ならなければそう記録する)。

## 7. 落とし穴

- **`s > 1` は反転なので、B 側でそのヘッドが逆向きに書いている場合、その分も反転して狙いと逆に押す**。強さを上げるたびに B 側を測り直す。
- **自動判定は取りこぼす**。判定語の一覧で数えると、言い回しを変えた該当例を見落とす。可能なら judge を併用する。
- **少数例では 1 件の差が大きく見える**。候補を絞る段階は少数で回し、最終候補だけ件数を増やす。
- **射影の値の目標は振る舞いの目標ではない**。同じ「B 側の平均」を目標にしても、振る舞いによって近すぎたり遠すぎたりする。迎合では greedy が L20 H18 の s=15 で目標に届いたが、振る舞いには弱すぎて、使えたのは s=38 だった。強さをどこまで上げるかは、調整に使っていない問題で生成して確かめる。
- **s の上限を外すだけでは解決しない**。`s ∝ η` のまま目標が遠いと、届かせようとして壊れる強さまで上がる。上限(既定 30)に当たった組は、表の `stop` と `capped` で分かる。上限で止まった値に意味はない。
- **s の大きさはヘッドで意味が違う**。同じ s=30 で、壊れないヘッドもモデルを全壊させるヘッド(L0)もある。残差のずれも、どの組にも使える安全の目安にはならない(ずれ 0.31 で、正答率が変わらない組も 6 ポイント下がる組もある)。モデルが全壊したかの検出くらいに使う。
- **読んだ応答に合わせて作った正規表現を、読んでいない応答に使わない**。見逃しが増える。件数が大事なら、応答を読んで判定する手順を入れる。
- **評価の問題が易しいと強さの差が見えない**。天井に近い問題で探すと、残りにくい例を消す調整が見えない。振る舞いが確実に出る、効きにくい問題で評価する。
- **目的指標を限界まで詰めない**。数 % はサンプリングの揺れ。強さを上げても下がらなくなったら、そこで止めて「残る例を担っている別のヘッドを探す」方に切り替える。
- **射影の値だけで主張しない**。射影の値は「方向で押したものを方向で測っている」ので、トートロジーに見える。必ず**外から見える指標**(出力に対する判定)を主指標にする。
- **未検証の使い方を明記する**。多ターン会話、system プロンプトあり、言い換えた入力は、挙動が変わる可能性がある。
- 比較対象が別のファイル(別の量子化)なら、その差も混ざる。
- **分かっている限界: 効くヘッドが候補から漏れることがある**。`gne heads pipeline` の候補の決め方には、次の 3 か所で漏れる余地がある。どれも arch によらない共通の処理。
  1. 最初の測る層(既定は基準層)より後のヘッドは候補にしない。
  2. ヘッド単位で測るのは、層ごとに全部のヘッドを止めた下がり方の上位 4 層(`top_layers`)だけ。
  3. 効率で配り直すとき、止めたときの効き目が大きいヘッドが外れることがある。一括と `gne heads allocate` の出力には、最初の組(効き目に比例)を同じ物差しで測った 1 行と、配り直しで外れたヘッドを出す(推す組の決め方は変えていない)。

  SenseNova-Loop-9B(docs/sensenova_loop.md)では、言語を変えるヘッド(ループの外の段 52)が 2 と 3 で漏れ、選ばれた組は振る舞いを変えなかった。

  Qwen3.5-4B(Q8_0、32 層)でも、1 の漏れは起きた。公開のひな形 2 つで、(A) v0.7.0 までの既定(`--rank causal`)と、(B) `--score-layers 16,24,30 --select-layer 30 --always-layers 27-29`(最後に測れる層で選び、それより前の全部の層を候補にする)を、6 ヘッドで比べた。振る舞いは、方向づくりに使っていない質問の各側 30 問で、書き終えた応答のうち `validate.match` に一致した数。

  | | question_kinds | disclaimer |
  |---|---|---|
  | 基準層 | 2 | 12 |
  | (A) の組の層 | 1 だけ(6 個) | 7・11 |
  | (B) の組の層 | 19・24・27 | 19・21・24・27 |
  | 層 30 で縮めた割合 / B 側のずれ | (A) 0.53 / 0.06、(B) 1.02 / 0.08 | (A) 0.33 / 0.23、(B) 1.01 / 0.18 |
  | A 側の一致(無介入 → (A) → (B)) | 29/29 → 0/30(30 問とも空の応答) → 1/29 | 28/30 → 9/29 → 27/30 |
  | B 側の一致(無介入 → (A) → (B)) | 0/29 → 0/29 → 0/29 | 1/26 → 3/27 → 0/28 |

  question_kinds では (B) が日本語の質問への答えを英語に変え、(A) はモデルを壊した(空の応答)。disclaimer では逆に、(A) が注意書きを減らし、(B) は層 30 の射影の値を B 側の平均まで下げたのに振る舞いを変えなかった。どちらの選び方も、いつもよいとは言えない。`--rank causal` に `--score-layers`(層の番号)・`--select-layer`・`--always-layers` を付けると、どのモデルでも (B) の形で流せる。

  この 3 か所を置き換える選び方として、`--rank writes`(§3.9)を足した。全部の層の全部の部品を候補にし、効き目の大きい部品を配り直しで外さない。question_kinds では 2 つのモデルとも今までの流れより良かったが、4B の disclaimer では、射影の値は届いても応答を変えず、今までの流れ(基準層の手前の層 7・11 のヘッド)に負けた。v0.8.0 から一括の既定は `--rank writes`、今までの流れは `--rank causal`(§3.9 の使い分け)。
- **分かっている限界: 直接の書き込みで選ぶと、射影の値は届いても応答が変わらないことがある**。4B と SenseNova の disclaimer で、`--rank writes` の組は最後に測れる層の射影の値を B 側の平均まで下げたが、注意書きを含む応答の数はほとんど変わらなかった。MLP のニューロンを足しても同じだった。

## 8. 時間の目安

生成を伴わない工程が大半なので、調整のループは速い。27B クラス・GPU 1 枚での目安:

| 工程 | 時間 |
|---|---|
| 方向を測る(数十件の prefill) | 10 分程度 |
| 止めたときの効き目の測定(層単位 + 数百ヘッド、1 ヘッド数秒) | 20〜30 分 |
| 組を作る・強さを配り直す(生成なし) | 1 組 2〜3 分 |
| LoRA 書き出し / マージ | 数秒 / 数分 |
| 確認用の全件評価(生成あり) | 1 組 30〜40 分 |
| 長いタスク・道具呼び出し | 30 分程度 |
| perplexity | 数分 |

**候補を絞るまでは生成しない**のが要点。生成を伴う評価は、確定候補の数だけに使う。

## 9. gne での手順

| 手順 | コマンド(MCP のツール) | 生成 |

| 3.2 基準層・後段の層とのコサイン、3.3 速い指標 | `gne direction score --name <方向>`(`direction_score`) | なし |
| 3.4 止めたときの効き目で絞る | `gne heads causal --name <方向>`(層単位 → ヘッド単位、`heads_causal`) | なし |
| 振る舞いを数える(応答を作り、正規表現の一致と judge の判定を数える) | `gne behave --prompts q.json --recipe R --match <正規表現> --judge <文面> --max-tokens 1024`(複数の `--recipe` は重ねる。`--thinking`・`--temperature`・`--seeds`) | 応答ごと |
| 方向の違う組を 1 つのレシピにする | `gne recipe-combine a.yaml b.yaml -o ab.yaml` | なし |
| attention の出力だけから方向を消す(全ヘッドの射影、MoE でも LoRA) | `gne headproj ablate --direction <方向> --per-layer`(`--bake` でマージ) | なし |
| どこを探すかを決める(方向の差を attention・専門家・共有の専門家に分ける) | `gne heads writers --name <方向>`(`--expert-layers` で専門家ごとにも) | なし |
| 3.5〜3.6 組を作り、効率で配り直す・ヘッド数を減らす | `gne heads allocate --name <方向> --target <射影の値>`(`heads_allocate`)。比を固定しないなら `--method greedy` | なし |
| 3.9 全部の部品(ヘッド・線形注意・ニューロン)を書き込みの量で並べ、上位を確かめる | `gne heads writes --name <方向>`(`heads_writes`。`--unit-kinds heads` でヘッドだけ、`--verify-top 0` で確かめない) | なし |
| 3.9 その順位で組を作る(s=1 から) | `gne heads pipeline --spec <JSON> --rank writes`(`--unit-kinds heads / all`、`--n-units 24,12,6`、`--check-replies 0` で応答の確かめを切る) | 応答の確かめだけ |
| ニューロンの射影が式どおりか | `gne headproj check --layer L --neuron N --direction <方向>` | なし |
| 3.2〜3.6・3.9 をまとめて回す | `gne heads pipeline --spec <JSON>`(`heads_pipeline`、UI の「CHiPS」の画面で JSON を読み込んでも回せる。用途別のひな形は `configs/pipeline/`)。既定は §3.9 の `--rank writes`、§3.4〜3.6 の流れは `--rank causal` | 応答の確かめだけ(`--rank writes`) |
| 組で消し切れない質問から、足すヘッドを探す | `gne heads refine --name <配分> --n-heads N`(`heads_refine`、UI の比較表の「残りから追加」)。組を当てても射影の値が目標まで下がらない質問を A、元の B を B にし、両側に組を当てたまま方向を作り直して `heads pipeline` に流す。元の組と合わせたレシピを作り、元の方向・元の目標で前後を測り直す(rank writes は s=1 の組も)。代表の合わせたレシピで応答での確かめ(`--check-replies`)。結果に重ねると、土台はその行の合わせたレシピ(元の組 + それまでの回の追加の全部)。部品ごとの何回目・2 つの方向で入った同じ部品が残る。強さを上げるのは足した組だけ。強さの候補もこの結果からは合わせたレシピで作る。推す行は合わせたレシピの数(元の方向・元の目標)で選ぶ: 足すと残りが増える・組の効きが下がる・B 側の上限を超えて土台より悪くなる行は推さず、良くなる行が無ければ推さない(足さないほうがよい)。推す行の応答が壊れていれば次の行(v0.8.4)。元の一括が質問を分けていれば、合わせたレシピの数を選ぶのに使っていない質問でも測る(行の `holdout`)。同じ層を 2 回実行するモデルで、土台と足した組が同じ重みを別の回の段で使う行には注(`cross_visit`。探したときは別々の LoRA で足し合わせ、合わせたレシピでは 2 つの射影を続けて掛けるので、強さが 1 を超えると効き方が大きく違うことがある。SenseNova の試しで、土台 s6 と足した s3 が同じ重みを別の回で使うと、段 51 の A 平均が 100 以上違った) | なし |
| 全体の倍率を応答で決める | `gne heads candidates --alloc <配分>`(組 × 倍率で応答を作り、どの候補か伏せた採点のファイルを書く)→ 採点 → `gne heads candidates --tally <名前>`(`heads_candidates`・`heads_candidates_tally`、UI のパイプラインのタブからも) | あり |
| 3.7 書き出す | `gne headproj export --recipe <レシピ>`(`--bake` でマージ、`--verify` で LoRA 版との一致) | なし |
| 3.8 評価する(ランダム対照・全層射影との比較) | `gne eval --recipe <レシピ> --random-controls 16`、`gne eval --recipe <レシピ> --compare-methods`、`gne eval --alloc <方向> --n-heads 6,5,4,3`(`eval`) | あり |

対照集合の両側は、system の代わりにレシピを当てて作ることもできる(`recipe_a` / `recipe_b`)。側ごとに別の質問を読ませることもでき(`prompts_a` / `prompts_b`)、§3.0 の「A 側と B 側のプロンプト」はこの形で書く。ニューロンのレシピが作った振る舞いについて、方向とそれを運ぶヘッドを探すときに使う。

候補の範囲は、どのモデルでも次の指定で変えられる。`--score-layers 16,24,30`(射影の値を測る層を数で渡す)と `--select-layer 30`(順位づけと配分の目標に使う層。この層より前のヘッドが候補になる)は `gne heads pipeline` と `gne heads causal` の両方、`--candidate-layers`(候補を探す層を絞る)は `gne heads pipeline`、`--always-layers 27-29`(層単位の順位に関係なくヘッド単位で測る層)・`--top-layers`・`--n-heads`・`--hard` は `gne heads pipeline --rank causal` だけ。`--score-layers loop` は同じ層を 2 回実行するモデルだけ。一括と `gne heads allocate` の出力には、最初の組(効き目に比例)を同じ物差しで測った 1 行と、効率で配り直して外れたヘッドも出る。

ユニットは `L:Hh:sS@NAME`(例 `33:H16:s6@evil`)、レシピでは `{layer, kind: head, head, mode: proj, direction, s}`。ニューロンは `L:Nn:sS@NAME`(例 `20:N4096:s1@evil`)、レシピでは `{layer, neuron, mode: proj, direction, s}`。層の書き込み全体は `L:attn:sS@NAME`・`L:ffn:sS@NAME`、レシピでは `{layer, kind: attn, mode: proj, direction, s}`(`kind: ffn` も)。方向を省くとレシピの `default_direction`、`direction_layer: base` で全ヘッドに基準層の方向を使う。判断の仕方は [agent_playbook.md](agent_playbook.md) §4.4。

## 10. 基準層より後ろのヘッドを確かめる(`gne heads tf`)

`gne heads pipeline` の因果の確かめは、「ヘッドを止めたときの、基準層での射影の値の変化」で測る。基準層より後ろのヘッドは、
仕組みのうえで 0 になり、測れない。`gne heads tf` は、無介入の応答を読ませ(teacher forcing、生成はしない)、ヘッドの方向成分を
弱めたとき(proj、強さ `--s`)に、次の 3 つを測る。順番は、層ごと(その層の全ヘッドを同時に)→ ヘッドごと。

- (a) 対象の文のトークンの対数確率の下がり方。それ以外のトークンの変化を引いたもので、大きいほど対象の文に効く。
- (b) それ以外のトークンの対数確率の変化の絶対値の平均。小さいほど、ほかへの影響が少ない。
- 終了トークンの対数確率の変化。

```bash
gne heads tf --contrast C --direction NAME --target 'ahoy|matey' --layers 1-27 --s 10 --name pirate_tf
```

- **対象の文**: 対照集合の片側(`--side a` = system_a / user_prompts の側。既定)の質問に、無介入で応答を作る。応答の中で
  `--target`(正規表現)に一致した文字を含む文(`--span sentence`。句点・改行で区切る)か、一致した文字そのもの
  (`--span match`)のトークン。それ以外のトークンは、応答ごとに `--others` 個まで選ぶ。
- **書き終えた応答だけ**を使う。応答の終わりに出る振る舞いは、長さの上限で切れた応答では「出なかった」が確かでない。
  `--max-tokens` は十分に取る。上限で切れて除いた数も出る。
- ヘッドごとに測る層は `--heads-layers` で指定できる。省くと、層ごとの (a) が正で、かつ層の (a) の中央値以上の層。
- 選ぶときは (a) が大きく (b) が小さいヘッドを探す。比 (a)/(b) を使うときは、効き目の小さすぎるヘッドが比の上位に来ないよう、
  (b) の上限を決める集まりの作り方に注意する。効き目がほとんど 0 のヘッドを多く足すと、中央値が下がる。
- Qwen3.5-4B での確かめ(注意書きを題材に、層 1〜29 を層ごとに測った): (a) が大きいのは層 7・8・12・1・6。基準層 13 より後ろでは
  層 20・24 だけが中央値を超えたが、その 2 層の 64 個のヘッドは 1 個ずつではどれも小さかった。
